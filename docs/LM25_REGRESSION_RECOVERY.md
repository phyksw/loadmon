# LM25 기존 기능 보존과 회귀 보완

2026-09-10. 사용자가 제보한 PC 자료 누락·MM 저하·월간 리뷰 문제를 LM24 기준선과 비교하고, 워크플로우 접기와 이동 준비 통합을 함께 반영했습니다.

## 변경한 동작

| 영역 | 현재 동작 |
|---|---|
| 담당자 워크플로우 | 상위 업무 성격 → 과제 → 담당 업무를 중첩 접이식으로 표시. 상위·과제 전체 접기/펼치기, 화면 갱신 시 상위 접힘 상태 유지. 역할·근거·단계·MM·혼재·미분류·얕은 신호 안내 보존 |
| PC 이동 준비 | 기존 버튼/BAT에서 프로그램 정리 → 폴더 확인·원복 → 이동 ZIP 생성·검증. 빠른 이동 BAT도 이 경로로 통합. ZIP 생성 전에는 완료라고 표시하지 않음 |
| PC 자료 보관 | 이전 PC 자료 보관 또는 PC 이름표 저장에 실패하면 새 수집 중단. 이전 이름표와 원본·부분 보관본을 보존하고 재시도 가능. 연결점·링크를 통한 다른 폴더로의 이동은 시작 전에 거부 |
| PC 기록 탐색 | `data/pc/pc_on.csv`와 평면 배치 `data/pc_on.csv`, 추가 PC의 같은 배치를 지원. 동일 날짜·겹치는 구간을 중복 가산하지 않음 |
| 수집 자료 표시 | 작은 CSV 한 행도 수집 자료로 인식. 본 PC·추가 PC의 PC 가동/구간 파일과 실제 출처 경로 표시. 구간 파일의 시작·끝 열도 표시 |
| 월간 리뷰 기간 | 기본은 현재 대시보드와 같은 분석 기간. 보존된 과거 기간을 선택해 열 수 있으며 서로 다른 기간의 신호·코멘트를 혼합하지 않음. 현재 기간의 신호가 없으면 누락 사실을 표시 |
| 월간 코멘트 | 일부 달의 재생성이 실패하면 그 달의 이전 코멘트를 보존하고 이전 내용임을 표시. 저장 실패 시 기존 파일 보존. 분석·재생성 완료 후 열린 리뷰 탭 자동 갱신 |
| 얼린 보고서 | 해당 보고서의 한 기간만 선택 가능. 같은 기간의 월간 코멘트를 표시하고 다른 기간·변경 요청은 차단 |

이동 준비는 대상 설치의 실제 실행 파일·명령줄 경로로 프로그램을 식별합니다. `LoadMonitor25 backup` 같은 공백이 들어간 형제 설치와 다른 브라우저 프로필은 종료하지 않습니다. 폴더 원복 실패·기존 ZIP 충돌·ZIP 실패는 미완료로 처리합니다.

## LM24 비교에서 확인한 사실

수정 전 PC 수집기·파서·MM 계산과 월간 리뷰의 핵심 함수는 LM24와 동일했습니다(제품명·주석 변경 제외). 기능 코드가 일괄 삭제된 것으로 확인되지는 않았습니다. 다만 기존 공통 결함과 실제 자료 연결 문제를 구분해 확인할 필요가 있습니다.

합성 자료에서 확인한 문제는 다음과 같습니다.

- 이전 PC 폴더 보관에 실패해도 PC 이름표를 바꾸고 수집을 계속해 기존 파일을 덮을 수 있었음.
- PC 자료가 정상 하위 폴더에 있어도 단순한 수집 여부 검사가 놓치고, 자료 보기 화면은 추가 PC나 평면 배치의 PC 기록을 빠뜨렸음.
- 다른 기간의 신호 파일이 나중에 갱신되면 대시보드와 리뷰 기간이 달라질 수 있었음.
- 월간 코멘트 일부만 성공하면 성공한 달만 저장하면서 기존 다른 달이 사라질 수 있었음.
- 재생성이 완료되어도 현재 열린 월간 화면은 탭을 다시 누르기 전까지 갱신되지 않았음.

표준 배치의 같은 PC 자료에 대한 시간·월별 MM을 LM24와 대조했습니다. 평면 배치의 새 호환 경로도 LM24 표준 배치와 같은 시간으로 계산되는지 확인했습니다. MM을 임의로 높이거나 계산 계수를 변경하지 않았습니다.

## 검증 범위와 실제 제보의 남은 확인

TEMP 합성 자료와 모의 프로세스로 보관 실패·재시도·PC 이름표 실패·ZIP 보존·다른 설치 제외를 검증했습니다. TEMP의 실제 Windows 연결점으로 원본 보존과 수집 중단도 확인했습니다. 월간 UI는 실제 PAGE JavaScript를 Node에서 실행하고, 얼린 보고서의 fetch 차단 코드까지 함께 확인했습니다. 브라우저에서는 합성 워크플로우의 상위 접기·전체 접기·다시 펼치기를 직접 확인해 하위 역할과 근거가 보존되는 것을 확인했습니다.

최종 `scripts/Test-Project.ps1` 전체 검사 결과는 **PASS**입니다. Python/JSON/TOML 문법, Ruff, PowerShell 파서, 실제 PAGE/TEAM_PAGE JavaScript, BAT/PS1 인코딩, 필수 71개 파일과 FILES 크기·CRC, 기존 7관문을 통과했습니다. 회귀 테스트 **116개 중 115개 통과, 1개 건너뜀**입니다. 건너뛴 항목은 Windows 권한이 필요한 심볼릭 링크 생성이며, 실제 연결점(junction) 검사는 통과했습니다. 로그는 `verification/lm25-check-20260910-013930-179.txt`입니다.

PC 보관·이동 준비·월간 보존·얼린 보고서 변경은 구현자와 다른 담당자가 독립 검토했습니다. 기존 월간 JSON의 일시 읽기 잠금도 실제 TEMP 파일로 재현하여 저장 거절과 이전 코멘트 보존을 확인했습니다. 검사에는 실제 회사 계정·Copilot·수집기·사용자 PC의 프로세스 종료를 사용하지 않았습니다.

현재 접근 가능한 개발본 `D:\배포\_gpt\LoadMonitor25`의 `data/`와 `report/`에는 파일이 없습니다. 실제 MM이 줄어든 설치의 자료나 실행 기록을 대조하지 못했으므로, 사용자 제보의 원인을 확정하거나 실제 MM을 복구했다고 주장하지 않습니다. 해당 실행 폴더와 분석 기간이 확인되어야 LM24 결과와 실제 입력의 누락·기간·설정 차이를 추적할 수 있습니다.

LM24 기준선은 수정하지 않았습니다. 이번 변경의 Git 커밋·푸시 및 실제 사용자 자료 이관은 수행하지 않았습니다. 사용 방법은 [빠른 이동 안내](../LoadMonitor25/docs/빠른이동.md)를 참고합니다.
