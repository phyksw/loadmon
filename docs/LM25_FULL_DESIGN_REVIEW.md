## 유지할 강점

1. 시간 구간 합집합: 겹치는 2h 회의 두 개를 3h, 두 PC의 겹치는 3h 구간 두 개를 5h로 계산하는 합성 검증을 통과했다.
2. 업무 구조: 네 상위 범주, 담당 업무와 활동 유형 분리, 60% 경계의 혼재 표시, 사용자 상위 지정 우선은 목적에 맞다.
3. 병합의 제약: 캐시 없는 경우 금지 쌍의 간접 합류 방지와 무리 크기 5 제한을 합성 검증했다. 이를 기존 캐시에까지 보장하면 된다.
4. 코드 계산과 AI 해석 분리: MM을 AI가 직접 만들어내지 않고 코드가 자료에서 계산하는 방향을 유지한다. 그 계산의 의미와 연결 ID를 바로잡아야 한다.
5. 현장 지원: 수집 폴백·부분 결과·진단·전송 대기·원본 보존·정적 보고서·내장 Python·개인자료를 제외하는 패키징이 갖춰져 있다.

## LM25에서 먼저 확정할 공통 데이터 규칙

대규모 전면 재작성이나 새 프레임워크 도입을 먼저 할 필요는 없다. 기존 모듈 경계에서 주고받는 결과를 아래 여섯 종류로 명확하게 만들고, 공통 계산·검증 함수를 함께 쓰는 방식이 적절하다.

| 데이터 | 필요한 필드와 규칙 |
|---|---|
| 관측 근거 | observation_id, device_id, 원본/수집 경로, 발생시각·정밀도, 기간, 실제 관측/AI 추출, 업무/비업무/미확정. 포함·제외가 모든 후속 계산에 동일하게 적용되어야 한다. |
| 업무와 병합 계보 | project_id, task_id, 표시 이름, 원본 업무 ID, 병합/분리·사용자 교정 이력. 이름 변경으로 다른 업무와 합쳐지지 않아야 한다. |
| 시간·MM | 사람 업무 구간, 무인 가동, 직접 귀속/가중 추정/미배분, 확정 부재/수집 공백, 공통 산식·근무일·설정 해시. 0과 미확정을 구분한다. |
| AI 판정·후보 | 입력 ID별 처리/무매칭/미확정/실패 상태, 검증한 evidence_ids, 적합도, 관련 업무량, 중복 제거 관련량, 후보별 안분량. 예상 절감량은 검토된 시간·횟수·절감률 근거가 없으면 비워 둔다. |

| 사용자 검토 | 대상 ID, 변경 전후, 이유, 검토 시각, 적용 기간/실행, 영향받는 산출물. 사용자 금지와 지정이 캐시 적용 후에도 우선해야 한다. |

자동화 후보를 실행 과제로 전환할 때는 입력·산출물, 접근 가능한 시스템, 반복 횟수, 예외·사람 검토, 품질 기준, 기준 소요시간, 시범 구현 후 실제 절감·재작업 비용을 갖춘다. 현재의 fit 점수나 과제 목록에 쓰인 목표 KPI만으로 효과를 확정하지 않는다.

## 권장 구현 순서와 통과 기준

| 단계 | 작업과 담당 | 완료를 판정할 사례 |
|---|---|---|
| 1. 측정·제외·비교 기준 | measurement 주도, workflow/reporting 연결. 사람/기계시간, 제외·미확정, 수동 구간, 공통 가용 분모, coverage 기준을 확정한다. | 개인 창 1h 제외 후 업무 0.5h 유지; 무인 계산으로 인간 시간이 증가하지 않음; 관측 누락만으로 부재·가용 분모가 바뀌지 않음; 비중복 수동4+PC4=8h, 완전중복=4h. |
| 2. 업무·근거·사용자 교정 | workflow 주도. 안정 ID, enum, 근거 허용집합, 최종 병합 제약을 적용한다. | 과제 A ID는 A의 0.2 MM만 연결; 없는/다른 업무·기간 근거는 보류; cached 병합 뒤 never 적용 시 실제 분리; 비업무 몫이 생존 업무에 조용히 재배분되지 않음. |
| 3. 실행·집계·보고 통일 | reporting 주도, workflow/운영 연결. 실행 묶음·재개 무효화·member ID·공통 지표와 비교 집합을 적용한다. | 이전 기간·stub의 현재 집계 기여 0; 잘린 답은 미완료; 단계 문구 분할로 절감량 불변; 같은 지표의 개인/UI/HTML/팀 값 일치; 실패/동시 읽기에 완전한 실행만 노출. |
| 4. 운영·현장 검증·배포 | 운영 담당과 독립 quality. 옵션·API·프로세스 소유권·부분 상태, 부가기능 지원 범위, 문서/표시 버전을 정리한다. | --no-teams 모든 경로 호출0; 잘못된 JSON 뒤 정상 실행 가능; 다른 설치 프로세스 선택0; 동명이인 분리; 실제 Windows 패키지 시작/복구 및 동의한 현장 자료 대조. |

각 단계는 구현자와 다른 `lm25_quality` 역할이 독립 검토한다. 제품 전체를 한꺼번에 바꾸기보다 공통 규칙을 먼저 확정하고 작은 단위로 회귀를 통과시키는 편이 기존 기능을 보존하기 좋다. 앞 단계의 산식·상태가 바뀌면 뒤 단계의 캐시와 보고서를 반드시 무효화해야 한다.

현장 검증에서는 문서/개발/해석/현장 직무, 단일/다중 PC, 수집 경로별 누락, 회의·출장·반차·샘플러 중단을 포함한 동의된 일지와 대조한다. 일 투입 오차·업무 귀속 오차·미배분 비율·수집 완료율을 직무별로 평가한다. 허용 오차는 사용 목적과 함께 정해야 하며 이번 코드 검토만으로 임의 인증 수치를 정하지 않았다.

합성 재현은 결함의 존재와 특정 입력에서의 동작을 확인한다. 실제 발생 빈도·회사 환경 수집 성공·AI 판정 정확도·실제 절감량을 증명하지 않는다. 범위와 대체 함수는 각 증거 파일에 기록했다. 운영 검증은 실제 프로세스/서버 경쟁을 실행하지 않고 명령 캡처와 파일 교체 경계 관찰을 사용했다.

제품 소스와 원본 설치는 변경하지 않았다. 변경물은 검토 문서·합성 재현기·증거·개발 README/계획 안내다. 실제 수집, 개인 설정/자료를 이용한 시험, 브라우저/Copilot, 서버 시작, 스케줄러 등록, 업로드, 배포 ZIP 생성은 수행하지 않았다. 린트·격리 기반 검증 결과는 별도 검증 기록에 남기며 위 결함의 개선 완료로 해석하지 않는다.

이 문서는 초기 [LM25_PLAN.md](LM25_PLAN.md)의 다섯 가지 선별 검토를 확장한 현재 전체 우선순위다. 기존 문서는 이력으로 보존한다. 목적 문서에 “되살리지 않을 폴백”으로 적힌 무관한 evidence 사용 경로가 실제 현 소스에는 남아 있는 점도 이번 W4에서 확인했다.
