# LM28 현장 점검 — 회사 PC(메일 계정·팀즈가 있는 PC)에서 확인할 것

개발 PC 에는 회사 메일 계정이 없어서 Outlook 앱·Outlook 웹·팀즈 웹의 실제 화면은 회사 PC 에서만 확인된다.
아래 순서로 한 번 돌리고, 표의 값을 적어 두면 수집기를 실제 화면에 맞출 수 있다. **제목·이름·본문은 적지 않는다 — 건수와
사유 코드만.**

## 0. 준비
- 폴더를 통째로 복사(또는 배포본 압축 해제) → `LoadMonitor28-UI.bat`.
- [AI 연결 진단] → 전용 Edge 창(프로필 `data\lm28_edge`)에서 회사 계정으로 **한 번** 로그인. 로그인 대기 중에는 창을 닫지 않는다.
- 같은 PC 에 LM24 가 있어도 된다 — 예약 작업·포트·Edge 프로필·임시 파일 이름이 다르다(README 'LM28 변경점').

## 1. 수집 한 번 — 기본 기간(올해 1월 1일 ~ 오늘)
[분석 실행] 또는 `LoadMonitor28.bat` 1번. 끝나면 확인할 파일:

| 파일 | 볼 것 |
|---|---|
| `report\last_run.json` | 단계별 rc·reason·counts. rc 0 정상 · 1 대상 없음 · 2 로그인 필요 · 3 불가·불완전(reason 필수) · 4 새 행 0 |
| `data\coverage_ledger.json` | 날짜 × 축(받은 메일·보낸 메일·일정·팀즈·PC) 상태. ok / zero_ok / partial / 미관측 / na 일수 — 화면 '수집 현황 — 날짜별 원장' 카드와 같은 값 |
| `data\outlook\src\mail_source_<출처>.json` | 출처별(COM·색인·웹·Copilot·반입) 행 수와 사유 |

## 2. 메일 — 경로별로 적을 값
| 경로 | 적을 값 | 기대 |
|---|---|---|
| Outlook 앱(COM) | 클래식/새 Outlook, 프로필 수, 월별 받은·보낸 건수, reason | 클래식이면 연결 성공. 실패면 reason 이 '의심' 표기인지. **R-COMCOLD** = 이 수집이 Outlook 을 직접 띄웠다(캐시 모드·새 Outlook 흔적) — 그 캐시가 사서함 전체인지 몰라 '0건 확인'을 적지 않고 색인·Outlook 웹이 확인한다(정상 동작) |
| 검색 색인 | 월별 메일·일정 건수 | COM 과 별개로 **매번** 돈다. 색인은 zero_ok 를 주지 않는다 |
| Outlook 웹 | `filter_ineffective`(날짜 필터가 무시됨) · `list_verified`(최신부터 끊김 없이 내려감) · `date_only` 비율 | 날짜 검색이 걸리면 filter_ineffective=false · list_verified 조각만 '읽음' |
| 일정(웹) | `weeks_unverified`(머리가 맞지 않은 주) | 0 에 가까울수록 좋다 |

## 3. 팀즈 — 적을 값
| 항목 | 기대 |
|---|---|
| 채팅방 수 · 읽은 방 수 | 수십 개 방이 있으면 대부분 읽혀야 한다(`teamsWebMaxChats` 기본 200) |
| `cut_no_scroller` | 메시지 스크롤 영역을 못 찾은 방 — 많으면 화면 구조가 바뀐 것(선택자 보정 필요) |
| `roomgone` | 방 재탐색 실패 — 그 방만 partial |
| `incremental` | 두 번째 실행부터는 새 메시지만 읽는지 |

## 4. 다시 실행 — 로그인 유지
같은 날 한 번 더 [분석 실행]. 전용 Edge 가 다시 로그인을 요구하지 않아야 한다. 회사 정책이 브라우저를 닫을 때 쿠키를 지운다면
`copilotAuto.keepEdgeOpen=true` 로 두고 다시 확인한다(R-EDGEKEEP).

## 4-1. 사진 한 장으로 보내기 — 수집 진단의 '구조:' 줄
`LoadMonitor28-수집진단.bat` 의 **[최근 실행]** 에서 Outlook 웹·팀즈 웹 단계 아래 들여 쓴 `[outlook-web] 구조: …`·
`[teams-web] 구조: …`·`… 구조+: …` 줄을 사진에 담는다. 글자는 x 로 가려져 있고(숫자·구두점·오전/오후만 남음) 이름·제목·주소는
없다 — 웹 화면의 어느 부분(목록·스크롤 영역·방 열기·대화 화면·일정 막대)에서 막혔는지가 이 줄에 나온다. 더 자세한 골격
(dom_census)은 바탕화면의 `LM28_수집진단_<날짜>.txt` 에 있다.
- `[outlook-web] 구조+:` — 위치 해석 n(열·눈금·종일줄) · 열머리/눈금/보정/시간칸/위치없음 · 뺌 칩(숨은일정)·옆칸 ·
  작은달력 성공/시도(칸·날짜꼴·달넘김·실패 까닭) · 못읽음 예 [표기꼴/까닭]
- `[teams-web] 구조+:` — 창 제목 꼴 · 누르기 방법별 시도/창 제목 바뀜 · 시각 수 · 대화 영역 data-tid 상위 · 목록 항목 잎 꼴 ·
  단계/펼침 · 읽은 경로(후보/일반) · 화면 보임·초점

## 4-2. 다음 실행 뒤 사진으로 보낼 것 — 판정·Agentic·워크플로우·시간 근거
[분석 실행](AI 판정 포함)을 한 번 돌린 뒤 아래 다섯 곳을 찍는다. 숫자와 사유만 담기게 찍고, 제목·이름·본문이 보이면 가린다.

| 찍을 것 | 어디서 | 볼 것 |
|---|---|---|
| `[judge] 구조:` 줄 | 대시보드 [진행 로그] — AI 판정 단계 끝 | 신호 · 재사용 · 같은 내용 대표 · 짧은 대화 · 왕복 · 대기 · 채움 · 규칙 · 중단. 다음 날 실행에서는 재사용이 크고 왕복이 적어야 한다(같은 로그의 '이어서 판정 — 지난 실행(다른 날짜 포함) N건 재사용' 줄도). 중단이 `throttle` 이면 사용량 제한 — 1~2시간 뒤 [재분석만] |
| Agentic 커버리지 줄 | Agentic AI 탭 위쪽(로그에는 `[agentic] 근거로 잡힌 업무 …`) | '근거로 잡힌 업무 X/Y행 · MM' 과 칩(미판정 · AI 판정 대기 · 개인정보 관문 · 과제와 무관). X/Y 가 낮으면 어느 칩이 큰지 |
| 워크플로우 탭의 이유 | 담당자 워크플로우 탭 | 흐름이 비었거나 일부만 나왔을 때 위에 뜨는 빨간 줄(멈춘 이유)과 '이어받음'·'AI 판정 대기 N개' 줄. '파싱 실패' 만 반복되는지, 사용량 제한·시간 예산 같은 실제 이유가 나오는지 |
| 리포트 '산출 방식' 표의 '퇴근 후·시각' 열 | 개인 리포트 '산출 방식 — PC 가동 하한의 근거' 절(최신순) | 야근·주말 근무한 날 몇 줄과 표 위 '시간 근거 합계' 줄 — '퇴근 후 Nh 인정' · 'PC 19시 이후 … → 미인정' · '날짜만 아는 발신 N통' · '표준일 추정' |
| 팀즈 '구조:' 줄의 '내 메시지' 조각 | 수집진단 [최근 실행] 의 `[teams-web] 구조: …` 끝 | '내 메시지 n/m · 판정불가 k · 이어받음 j'. 내가 보낸 글이 있는데 n 이 0 이거나 판정불가 k 가 크면 내 말풍선 판정이 화면과 맞지 않는 것(선택자 보정 필요) |

## 4-3. 프로그램 사용 이력 — 사진으로 보낼 것
실행 흔적은 Outlook 판과 무관합니다. 클래식 Outlook PC도 같은 방법으로 확인합니다.
프로그램 이름은 찍어도 되지만, 과제 코드네임이 든 이름은 가려 주세요.

| 찍을 것 | 어디서 | 볼 것 |
|---|---|---|
| '프로그램 실행 기록 (참고)' 줄 | 진행 로그 또는 수집진단 [최근 실행] — [분석 실행]·[로컬PC 자료수집] 뒤 | `[programs] 실행 기록 스냅샷 — UserAssist N건(바로 가기 n) · 작업 표시줄 N건 · BAM … → 프로그램 N개 · … · snap_….json (보관 N장)` 꼴인지. 'BAM 권한 없음(건너뜀 …)'은 정상입니다. **UserAssist 0건**, '읽을 수 있는 실행 흔적이 없습니다', "'앱 실행 추적' 이 꺼져 있어"가 보이면 꼭 알려 주세요 |
| `data\programs` 폴더 | 설치 폴더 | `snap_날짜_시각.json`이 하루 한 장 생기는지(같은 날 다시 돌리면 그날 장이 바뀝니다) |
| '프로그램 사용(참고)' 표 | 대시보드 'MM 산정 근거' 카드 아래 | 실제로 쓰는 상용 시뮬레이션(Ansys·Creo 등)이 보이는지, '마지막 실행' 날짜가 맞는지. 첫날은 '누적 N'과 '스냅샷이 1장뿐이라…' 안내가 정상입니다. 이튿날 다시 수집하면 '실행 기록 스냅샷 a~b 사이 증가분' 기준으로 바뀌어야 합니다 |
| '자체·프로토타입(추정)' 줄 | 같은 카드 | 실제 사내 도구·시험판이 보이는지, 엉뚱한 프로그램(무료 도구·게임 등)이 섞였는지. 잘못 분류된 것은 `programsExtra`로 바로잡습니다 |
| '도구 불명 파일' 줄 | 같은 카드 | '.prt N개'처럼 뜨면 그 PC에서 쓰는 도구(NX·Creo 등)를 알려 주세요 — `programsExtra`의 `ext` 칸으로 정합니다 |
| 분석리포트 1절 · 리포트 8절 | `report\`의 보고서 | 대시보드와 같은 표가 나오는지 |

팀 통합 보고서 11절은 아직 옛 꼴(창 기록 시간)이라 0.0h로 보일 수 있습니다. 알려진 것이라 따로 보내지 않아도 됩니다.

## 4-4. 버튼 · 팀 서버 자동 보고 — 사진으로 보낼 것
[분석 실행]은 이제 끝에 팀 서버로 자동 보고합니다. 사내망 밖에서 한 번, 사내망에서 한 번 돌려 두 경우를 모두 확인합니다.

| 찍을 것 | 어디서 | 볼 것 |
|---|---|---|
| 첫 줄 버튼 | 대시보드 | 파란 [분석 실행] 바로 오른쪽에 청록 [로컬PC 자료수집]이 있고, 오른쪽 회색 버튼 줄에는 옛 [추가 PC 수집]이 없어야 합니다. 마우스를 올리면 툴팁이 뜨고, 실행 중에는 두 버튼 모두 회색입니다. 위쪽 단계 표시는 '③ 팀 서버 보고(자동) / 공유폴더 저장'입니다 |
| 사내망 밖에서 [분석 실행] (사진 2장: 알림 창 + 배너) | 진행 로그 · 알림 창 · 화면 위쪽 | 로그에 '── 팀 서버 자동 보고'와 '[!] 팀 서버 자동 보고 실패 — 서버에 닿지 않음'. 끝나면 알림 창이 한 번 뜹니다('결과 묶음은 대기로 남았습니다…' 안내 포함). 빨간 배너가 남고, F5로 새로고침해도 알림은 다시 뜨지 않아야 합니다. 배너 [닫기]로 사라지는지, 업로드 카드에 '대기 1건'과 '● 마지막 자동 보고 … 실패' 줄이 있는지 |
| 사내망에서 [분석 실행] | 상태 글자 · 업로드 카드 · 팀 취합 화면 | 로그 '[teamup] 전송 완료: 성공 N / 실패 0', 상태 글자 '대기 중 · 팀 서버 보고 완료 (N건)', 카드 '● 마지막 팀 서버 보고 … N건 보냄(분석 끝 자동)'. 팀 취합 화면에 결과가 들어오고, 알림 창은 뜨지 않아야 합니다 |
| 실패가 남은 채 사내망에서 [팀 서버 업로드] | 대시보드 | 빨간 배너가 사라지는지 |
| [로컬PC 자료수집] 한 번 | 확인 창 · 진행 로그 | 확인 창이 새 문구인지. 로그 끝이 '[로컬PC 자료수집] 이 PC 의 자료 수집을 마쳤습니다 — AI 분석·팀 서버 보고는 하지 않았습니다.'이고, '팀 서버 자동 보고' 단계와 알림이 없어야 합니다. Outlook 웹·팀즈 웹 수집 줄은 [분석 실행] 때와 같게 나와야 합니다 |
| `LoadMonitor28.bat` 실행(실패할 때) | 콘솔 | 맨 끝 [완료] 안내 바로 위에 '[!] 팀 서버 자동 보고 실패 — …' 두 줄 |
| 자동 보고 끄기(확인 뒤 되돌리기) | `config\config.json`의 `teamUpload.autoReport`를 `false`로 | 업로드 카드 머리말이 '자동 보고 꺼짐…'이 되고, 다음 실행 로그에 '팀 서버 자동 보고 — 건너뜀'. 확인이 끝나면 `true`로 되돌립니다 |

## 4-5. 메일 폴더(Outlook 웹) — 사진으로 보낼 것
새 Outlook을 쓰는 PC(전용 Edge의 Outlook 웹)에서 확인합니다. 클래식 Outlook(COM) PC는 바뀐 것이 없습니다(이미 모든 폴더를 읽습니다).
업데이트 뒤 첫 [분석 실행]은 Outlook 웹이 지난 날을 한 번 다시 읽어 평소보다 오래 걸립니다(정상).

| 찍을 것 | 어디서 | 볼 것 |
|---|---|---|
| `[outlook-web] 구조:` 줄 끝의 '다른 폴더 r/f(…)' | 수집진단 [최근 실행] — 업데이트 뒤 첫 [분석 실행] | f(찾은 폴더 수)가 내 폴더 수(내가 만든 폴더 + 받은/보낸 편지함 하위 폴더 + 보관)와 비슷한지, 괄호 안 '끝 근거' 수가 r(읽은 수)과 같은지 |
| '다른 폴더 못 찾음(폴더 창 없음)' | 같은 줄 | 전용 Edge 창의 Outlook 웹에서 왼쪽 폴더 창이 접혀 있는지 보고, ☰ 단추로 펼쳐 둔 뒤 다시 실행 |
| '사서함 못 가림'·'전환 실패'·'펼침' 수가 큰 경우 | 같은 줄 + 바탕화면 `LM28_수집진단_<날짜>.txt` | 그 줄과 수집진단 파일을 보내 주세요(폴더 이름은 담기지 않습니다) |
| Outlook 웹 화면 | 실행 뒤 전용 Edge 창 | 내 폴더의 읽지 않은 수가 그대로인지(메일을 열지 않음), 즐겨찾기에 폴더가 새로 생기지 않았는지. 접혀 있던 폴더가 펼쳐진 것은 정상 |
| 규칙으로 옮긴 메일이 있는 날 | 수집 데이터 현황 · `data\outlook\mail.csv` | 그날 받은 메일 수가 업데이트 전보다 늘었는지 |
| '다른 메일 폴더: 시간 예산에 닿아 n개는 읽지 못했습니다' | 진행 로그 | 실행마다 나오면 알려 주세요 — 폴더 수 상한(`owaExtraFolderMax`)·제외 목록(`owaExtraFolderSkip`)을 조정합니다 |

## 4-6. 회의 안건(일정 본문) — 사진으로 보낼 것
[분석 실행] 뒤 진행 로그를 찍습니다. 본문 내용은 찍지 말고, 있다/없다만 적어 주세요.

| 찍을 것 | 어디서 | 볼 것 |
|---|---|---|
| '일정 본문(회의 안건) N건 정리' 줄 | 진행 로그의 '개인정보 정제' 단계(메일·일정 출처 파일) 아래 | Outlook 웹이나 클래식 Outlook이 회의 본문을 읽었을 때만 나옵니다. '자격증명이 남아 비운 본문 K건'이 함께 나와도 정상입니다 |
| `[judge] 회의 안건(일정 본문 정제) N건을 회의 판정의 참고로 붙입니다` 줄 | 진행 로그의 AI 판정 단계 | N이 0보다 큰지. '같은 시각·제목의 회의 신호가 없어 붙이지 않습니다'가 나오면 그 줄을 찍어 주세요(웹 일정의 시각·제목이 회의 신호와 어긋난 것). '개인정보 관문에서 뺀 안건 K건'은 정상입니다 |
| `[outlook-web] 구조+:` 줄의 '본문 a/b(상세 …·닫힘 …)' | 수집진단 [최근 실행] | 상세 수가 연 수(b)와 같고 닫힘도 같은지. '멈춤 주 보기 바뀜 / 안 닫힘 / 상세 안 뜸'이 보이면 사진을 보내 주세요 |
| Outlook 웹 일정 | 실행 뒤 전용 Edge 창 | 수락·거절·참가 같은 변화가 없어야 합니다(회의를 열어 본문을 읽고 닫기만 합니다) |
| 리뷰 탭 | 대시보드 | 출처가 '회의'이고 제목이 '주간 회의'처럼 일반적인 회의가 맞는 과제·세부업무로 가는지 |
| 새는 것이 없는지 | `report\signals_<기간>.csv` · `data\outlook\calendar.csv` 맨 끝 body 열 | signals에 안건 문장이 없어야 합니다. body 열에 링크·전화번호·회의 암호가 없어야 합니다. 화면 [데이터] 표에 본문 열이 보이지 않는 것은 정상입니다 |
| `[outlook] 일정 본문(회의 안건): 읽음 N · 빈 본문 · 비공개 · 보호 멤버라 안 읽음 · 오류` 줄 | 클래식 Outlook PC의 진행 로그 | 첫 수집에 '일정 본문 읽기 설정이 지난 수집과 달라 일정은 처음부터 다시 읽습니다(메일 달은 그대로)'가 한 번 나오는 것은 정상입니다. **Outlook 보안 경고 창이 뜨면 바로 사진**을 찍어 주세요(뜨지 않아야 합니다). '보호 멤버라 안 읽음'이 많으면 그 PC의 백신·보안 정책 때문이고, 본문만 비며 회의는 그대로 잡힙니다 |

업데이트 뒤 첫 분석은 안건이 붙은 회의만 AI에 한 번 더 물어 왕복이 조금 늘 수 있습니다. 두 번째 분석부터는 다시 묻지 않습니다.

## 4-7. Copilot 채팅 정리 — 사진으로 보낼 것
LM28은 이제 자기가 연 Copilot 채팅을 다 쓰면 대화 목록에서 지웁니다. [AI 연결 진단]을 한 번 누르고, [분석 실행](AI 판정 포함)을
한 번 돌린 뒤 아래를 찍습니다. 숫자와 까닭만 담기고 채팅 제목·내용은 담기지 않습니다. 대화 목록을 찍을 때 내 대화 제목이 보이면
가려 주세요.

| 찍을 것 | 어디서 | 볼 것 |
|---|---|---|
| 'Copilot 채팅 정리:' 줄 | [AI 연결 진단] 알림 창(진행 로그에도 '[진단] Copilot 채팅 정리:'로 남습니다) | '만든 1 · 지운 1'이면 삭제 흐름이 이 PC의 Copilot 화면과 맞는 것입니다. '지운 0'이거나 '남긴 1'이면 괄호 안 까닭을 찍어 주세요 |
| `── Copilot 채팅 정리` 아래 줄 | 진행 로그 맨 끝 — [분석 실행]이 전용 Edge를 닫을 때 | '만든 n · 지운 m · 남긴 k'. 지운 수가 만든 수와 같으면 정상입니다. 남긴 수가 있으면 괄호 안 까닭('대화 목록에서 못 찾음'·'메뉴에 '삭제' 없음' 등)이 보이게 찍어 주세요 |
| `[copilot] 채팅 정리:` 줄 | 진행 로그 — AI 판정·AI 정제·Agentic·워크플로우 단계 끝 | 단계마다 만든·지운·남긴 수. '이어 쓰는 채팅 1개는 다음 새 채팅·실행 끝에 정리'는 정상입니다(다음 단계가 지웁니다) |
| Copilot 대화 목록 | 실행 뒤 전용 Edge 창의 왼쪽 대화 목록 | LM28이 연 채팅(판정 요청·월별 리뷰 등)이 남지 않았는지, 내가 직접 만든 대화는 그대로인지 |
| '삭제 멈춤' 문구 | 위 줄 어디든 | 보이면 바로 사진을 보내 주세요 — 지운 뒤에도 채팅이 화면에 남은 것이라 그 뒤로는 지우지 않습니다 |
| '새 채팅으로 확인되지 않아 맡지 않은 채팅 n' | 위 줄 | n이 크면 이 PC의 Copilot 주소 꼴이 예상과 다른 것입니다 — 사진과 함께 전용 Edge 주소창의 주소 꼴(대화 id 자리만 x로 가림)을 알려 주세요 |

지우기를 끄려면 `config\config.json`의 `copilotAuto.deleteChats`를 `false`로 바꿉니다(설정가이드 §8-1).

## 4-8. 창 닫기 · 강제 종료 — 사진으로 보낼 것
이제 대시보드 창을 닫으면 도는 작업도 멈추고, 대시보드 서버와 검은 창도 닫힙니다. [분석 실행]을 누르고 진행 바가 움직이는 동안
아래 순서로 확인합니다. 작업 관리자의 '세부 정보' 탭에서 python.exe·powershell.exe·msedge.exe 를 찍을 때 명령줄 열을 켜 두면
좋습니다(이름·경로만 보이게, 다른 창 제목은 가려 주세요).

| 찍을 것 | 어디서 | 볼 것 |
|---|---|---|
| 창을 닫을 때 뜨는 확인 창 | 분석 중에 대시보드 탭의 X | 브라우저가 나갈지 한 번 묻는지. 나가기를 고르면 다음 줄로 |
| `[ui] 대시보드 창이 닫혀 실행 중인 작업을 멈추고 서버를 끝냅니다 (창 닫힘)` 줄 | 검은 콘솔 창(약 20초 뒤) | 이 줄이 보인 뒤 창이 저절로 닫히는지. 창이 '계속하려면 아무 키나…'로 멈춰 있으면 사진을 보내 주세요 |
| 작업 관리자 | 줄이 나온 뒤 30초쯤 | 이 폴더의 python.exe·수집기 powershell.exe·전용 Edge(명령줄에 `data\lm28_edge`)가 하나도 없어야 합니다. 팀 서버를 켜 두었다면 `teamserver.py` 하나는 남아야 정상입니다 |
| 새로고침 | 대시보드에서 F5 | 새로고침만으로는 끝나지 않아야 합니다(20초 안에 다시 이어짐) |

| 절전 탭 | Edge 설정에서 비활성 탭 절전 시간을 가장 짧게(5분) 두고, 분석 중 다른 탭에 15분 머문 뒤 대시보드 탭으로 돌아옴 | 분석이 그대로 돌고 있어야 합니다. 멈췄으면(화면이 '서버 연결 끊김'이거나 검은 창이 닫혀 있음) 바로 사진을 보내 주세요. 확인한 뒤 절전 시간은 원래대로 |

`uiAutoExit`를 `false`로 바꿉니다(설정가이드 §8-4).

## 5. 끝난 뒤
- 우리가 띄운 Edge·Outlook 은 닫혀 있어야 한다(작업 관리자에서 확인). 원래 열어 둔 Outlook 은 그대로.
- 원장의 '미관측' 날이 남았다면 그 날짜·축과 reason 을 적는다 — 0시간이 아니라 '모름' 으로 남는다.
- 위 값(건수·사유 코드)을 개발 쪽에 전달한다. 문제가 나오면 `run.py --web-only mail|teams` 로 그 경로만 다시 돌릴 수 있다.
