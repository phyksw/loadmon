# LM25 목적에 맞춘 개선 계획

2026-09-09 검토. LM24를 LM25 개발본으로 계승하되 먼저 결과의 의미와 근거를 명확하게 만드는 것이 목표입니다.

이 문서는 초기 다섯 항목의 선별 검토 이력입니다. 후속 요청으로 수집·측정부터 팀 보고·운영까지 검토한 현재 우선순위는 [전체 기능 설계 검토](LM25_FULL_DESIGN_REVIEW.md)를 따릅니다. 특히 사람시간·비업무 제외·신뢰도와 분모 문제를 업무 식별자 개선에 앞서 함께 해결해야 합니다.

## 이번에 완료한 기반 작업

- LM24 원본 101개 파일을 보존하고 LM25 작업본을 생성했습니다. 실행 파일명과 제품 참조를 LM25로 맞췄습니다.
- UI의 Python 이스케이프 경고 4건을 수정하고, UI를 포함하는 Ruff와 실제 HTML 문자열의 JavaScript 검사를 연결했습니다.
- 편집 후 검사, 완료 전 격리 검증, Git 인덱스 검사 훅과 4개 분야별 서브에이전트 역할을 구성했습니다.
- 기존 제품 문제 3개를 합성 자료로 재현했습니다. 아래 제품 개선 항목은 아직 구현하지 않았습니다.

## 우선순위와 완료 조건

행 번호는 LM25 초기본 기준입니다. 첫 세 항목의 실제 관찰은 [LM25_REVIEW_EVIDENCE.json](LM25_REVIEW_EVIDENCE.json), 재현기는 [review_probes.py](../scripts/review_probes.py)에 있습니다. 소스의 필요한 함수만 AST로 추출해 합성 입력으로 호출했고 앱 진입점·외부 서비스·실데이터는 사용하지 않았습니다.

## 작업 순서와 분담

1. `lm25_workflow`: 업무·근거 식별자와 AI 응답 검증 계약을 구현합니다. 기존 캐시의 전환 기준을 포함합니다.
2. `lm25_reporting`: 공통 MM 지표와 화면 문구를 정리합니다. 기존 export/report 소비자의 스키마 전환을 포함합니다.
3. `lm25_measurement`: 총시간 추정과 과제 배분의 설명·민감도를 검토합니다. 산식을 바꾸기 전에 동일 자료의 영향량을 비교합니다.
4. `lm25_quality`: 구현자와 독립적으로 완료 조건, 병합 제약·60% 혼재·사용자 상위 지정의 회귀를 확인합니다.

린트·훅 통과는 개발 기반의 정상 동작만 뜻합니다. 위 제품 검증, 실제 회사 환경의 Outlook·Teams·Copilot 검증, 패키지 실행 확인을 별도로 통과해야 LM25 배포 완료로 판단합니다.
