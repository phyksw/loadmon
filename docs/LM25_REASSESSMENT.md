# LM20·LM24 목적 재검토와 LM25 개선

2026-09-12. 사용자 요청에 따라 LM20·LM24는 읽기만 하고 LM25 제품과 그 검증·설명만 수정했다. 현재 상태는 이 문서를 기준으로 한다. 9월 9일의 `review_*.md`와 전체 설계 검토는 당시 결함·판정의 기록으로 보존한다.

## 목적과 계승 범위

검토한 원본은 `D:\자료작성\LoadMonitor20`, `D:\배포\loadmon24`, ZIP 기준선 `D:\배포\_gpt\LoadMonitor24`의 README·코드와 저장소의 기존 목적/검토 문서다. 개인 data·report·config는 읽거나 시험에 쓰지 않았다.

LM20은 활동 흔적·PC 하한을 통한 팀 업무 투입 파악과 다중 PC 수집, 팀 서버 식별, 보고서 보존을 중시한다. LM24는 이를 확장해 연구개발 산출물과 월간 근거, 과제 병합·업무 성격·담당 업무 흐름을 연결한다. 따라서 LM25의 중심 목적은 **근거 있는 인적 투입 추정 → 업무 구조화 → 팀의 AI 적용 우선순위 검토**다. PC 가동·AI 후보와 인력 절감을 동일시하거나, 빈 자료를 과거 결과로 채우면 목적을 훼손한다.

고정 상위 4분류, 사용자의 과제 지정, 60% 가중 다수/혼재, 병합 금지·크기 상한, 담당자 흐름, 월간 리뷰, PC 이동·추가 PC 보관은 유지한다. 이번 이전에 작업한 속도 개선·회귀 복구도 함께 보존한다.

LM20·LM24의 모든 결함이 같은 형태로 존재한다고 주장하지 않는다. 솔버 인정·결측 부재 추정 등 일부 보정은 LM24에서 확장됐으며, 확정 수치는 각 LM25 대상 함수에 합성 입력을 준 재현이다.

## 독립 검토와 검증 범위

측정·업무/AI·보고 담당이 영역별 구현을 나눴고 다른 담당자가 교차 검토했다. 교차 과정에서 정제 MM 재확대, 정당한 과제 병합 MM 축소, 원본 읽기 경합, Windows 긴 경로, 소문자 사용자 과제 ID의 캐시 거절을 찾아 추가 보완했다.

회귀는 TEMP 합성 자료·선택 AST·모의 AI 응답으로 수행한다. 실제 UI·팀 서버·수집·AI·업로드·사용자 프로세스를 실행하지 않는다. 생성 HTML/화면 JS는 Python 문자열 해석 후 Node로 검증한다. 전체 테스트 결과와 Git 반영 정보는 작업 완료 기록에 남긴다.

구버전 코드 보존은 검토 전/후 SHA-256 목록 비교로 검증한다. 기준선 `LoadMonitor24/`와 `docs/BASELINE.json`의 Git 변경도 없어야 한다.
