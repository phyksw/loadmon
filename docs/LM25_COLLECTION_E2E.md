# LM25 v25.6: 디지털 업무 근거 파이프라인

## 목적과 확인된 한계

메일·Teams는 업무 요청, 담당 역할, 응답, 결정, 산출물의 관계를 설명하기 위한 근거다. 메시지 수 자체가 근무시간이나 자동화 절감량은 아니다. PC별 자료가 다르면 같은 계정이라도 열린 앱·로컬 색인·전용 브라우저 로그인·설정·실행 모드부터 다를 수 있다.

사용자가 다른 PC에서 보고한 Teams 7건·메일 0건의 직접 원인은 실행 로그 없이 확정하지 않았다. 코드상 기존 Teams 경로에는 날짜 검색이 없었고, 추가 PC 수집은 기본 웹 생략이다. Outlook 웹은 공식 안내와 다른 날짜 검색문법을 썼다. 본문을 확보해도 flow/agentic 단계에서 제목과 짧은 표시문만 사용하는 구간이 있었고, 최소 여러 단계를 요구하거나 ID 연결 검증을 서술 사실 검증처럼 표현했다.

## 구현된 흐름

1. UI에서 상단 기간을 정하고 `메일·Teams만 수집 (웹 포함)`을 누른다. run.py는 통신 경로만 실행하고, `--interactive-collect`로 headless 기본값을 명시적으로 해제한다. 양쪽 Copilot 수집을 생략한다. Outlook 웹 본문은 사용자 선택 시에만 `--include-body`로 요청한다.
2. Teams 웹은 공식 `Sent:` 날짜 검색을 시도한다. Messages 결과 탭과 검색어를 확인하고, 날짜별로 가상 결과를 순회한다. 원문으로 이동해 방·메시지 ID·날짜를 확인한 뒤 주변 최대 앞뒤 6개 메시지를 보관한다. 날짜나 ID를 검색어에서 만들어 넣지 않는다. 검색 UI 미지원은 빈 결과와 구분하고 기존 방 탐색을 계속한다.
3. Teams 검색 예산은 전체의 45%, 최대 360초다. 날짜별 작업·시도 시각·미완료·관측 건수를 저장한다. 최근 날짜를 새로 읽고 이전 작업도 순환한다. 모든 UI 검색은 부분 범위이며 전체성을 주장하지 않는다.
4. Outlook 웹은 `received:MM/DD/YYYY..MM/DD/YYYY`, 보낸편지함은 `sent:`를 사용한다. 기본 7일 단위이며 결과 상한 또는 스크롤 한도에 닿으면 하루로 분할한다. 진행·관측 키를 저장하고 미완료 구간부터 재개한다. 대상은 받은편지함·보낸편지함이며 폴더/서버 검색 적용을 확증하지 못하므로 부분 수집이다. 실제 폴더 토큰이 없으면 발수신 방향을 단정하지 않는다.
5. 원문 접근 대안으로 EML/MBOX 가져오기를 제공한다. 명시적으로 선택한 파일·폴더만 읽으며, 기본 폴더 바로 아래만 탐색한다. MIME 본문·Date·Message-ID·References·In-Reply-To를 보존하고 첨부는 해석하지 않는다. Message-ID와 계정 기준 중복 제거, 충돌 별도 보존, 날짜 불명·기간 밖·형식 오류를 구분한다. 원본은 수정하지 않는다.
6. 기존 CSV와 추가 PC를 합쳐 기간별 고유 기록·본문·대화 묶음·불명 날짜·관측 출처를 계산한다. `source_coverage_ratio=null`은 원본 전체 분모를 모른다는 뜻이다. `context_ratio`는 관측한 기간 내 고유행 중 본문 비율일 뿐이다. 요약 JSON에는 제목·본문·상대·계정·파일 경로를 넣지 않는다.
7. mine → judge/refine → flow/agentic까지 제한된 원문 발췌와 근거 수준을 전달한다. 제목만 있는 통신 단위와 단계는 검토 대상으로 남긴다. 파일·커밋·수동 근거가 있는 다른 업무까지 메일 0건 때문에 막지 않는다. ID 연결은 `source_linked`, 서술은 `ai_inference`, `fact_verified=false`로 분리한다. 방향·시각을 확인하지 못한 메일은 내용 분류에 남겨도 시간 산정 근거로 쓰지 않는다.

## 사용자가 보는 결과

- 고유 기록 / 본문 포함 / 대화 묶음 / 한계 및 다음 조치.
- 경로별 완료·부분·실패·차단·생략과 요청 기간.
- import 완료·부분·실패 및 새 저장 건수. 지연된 이전 상태 응답이 새 실행 결과를 덮지 않는다.
- AI 해석·검토 필요를 구분하고, 수집 부족을 무업무나 확정 0시간으로 표현하지 않는다.

## 검증과 남는 제약

실제 회사 Teams·Outlook 연결 성공은 검증하지 않았다. 권한·로그인·라이선스·검색 색인·DOM 변경으로 계속 0건 또는 부분 수집이 가능하다. UI 탐색과 파일 가져오기는 정책 우회나 전체 서버 수집의 대체 보증이 아니다. 일반 실행의 기존 Copilot 보충은 설정에 따라 남지만 새 통신 전용 수집은 이를 호출하지 않는다.

합성 E2E는 Teams 단서 7건·메일 0건에서 EML 원문 3건을 가져온 뒤, 반복 가져오기 0개 추가·기간/대화 집계·실제 mine 실행·flow 프롬프트 본문 전달을 확인한다. 실제 AI 응답이나 회사 메일 접근 성공을 의미하지 않는다. 수집기별 가짜 브라우저·기간 재개·중복/ID/날짜 검증, 실제 PAGE 버튼 및 상태 경합 회귀를 별도로 실행한다. 전체 검사 결과와 배포 식별자는 최종 작업 결과에 기록한다.
