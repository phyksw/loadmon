## 목적

Windows PC에 남는 업무 활동을 근거로 개인과 팀의 업무 투입을 파악하고, 반복 업무·자동화 후보를 찾아 AX/Agentic AI 과제 기획에 활용하는 도구입니다.

1. 파일/CAD/해석 산출물, Git, PC 가동·창 활동, Outlook 메일·일정, Teams, 수동 기록을 수집합니다.
2. 신호를 업무 성격 → 과제 → 실제 담당 업무로 분류·정제하고 활동 유형은 별도로 유지합니다.
3. 시간 구간과 근거에서 투입 MM·가용 MM·로드율을 산정합니다.
4. 담당 업무별 워크플로우와 Agentic AI 적용 후보를 판정하고 개인·팀 보고서로 정리합니다.

흐름: `run.py` → 수집 → `mine.py` → `judge.py` → `refine.py` → `agentic.py` → `flow.py` → `freeze.py`. 팀 데이터 준비/전송은 `export.py`·`teamup.py`, 취합은 `aggregate.py`·`team_report.py`, 팀 서버는 `teamserver.py`가 맡습니다.

## 유지할 원칙

- 투입시간은 회의·샘플러·신호·PC 가동 구간의 합집합과 보정 규칙으로 추정합니다. PC가 켜져 있다는 사실만으로 전부 근무로 보지 않습니다.
- 투입 MM·가용 MM을 구분하고 `로드율 = 투입 MM / 가용 MM × 100`을 사용합니다. 월별 평일과 부재를 반영하며 야근 때문에 100%를 넘는 결과를 허용합니다. 과거 13h/16h 일 상한을 복원하지 않습니다.
- 신호 신뢰도, 측정 방식, 수집 결측, 산식 설정 차이를 함께 보여줍니다. 프로그램 사용 이력은 별도 지표이며 MM에 추가 가산하지 않습니다.
- 시간·MM은 코드가 근거에서 계산합니다. AI는 분류·정제·설명·자동화 가능성을 판정하고 근거가 부족하면 보류합니다.
- 정제는 과제 축이 맞는 `signals_*.csv` 근거를 사용합니다. 무관한 과제의 `evidence_*.md` 앞부분을 통째로 쓰던 폴백은 되살리지 않습니다.
- 실패는 `last_run.json` 및 UI에서 원인과 함께 확인 가능해야 합니다. 화면 문제는 먼저 화면이 읽는 보고서의 기간·경로·수정 시각을 확인합니다.
- 실제 수집 자료와 로그인 프로필은 현장에 둡니다. 실데이터를 삭제하거나 가짜 자료로 바꾸는 회귀 시험은 하지 않습니다.
