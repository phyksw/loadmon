# LM25 서브에이전트 운영

목적은 [PROJECT_CONTEXT.md](PROJECT_CONTEXT.md)의 시간·MM 신뢰성, 과제 분류와 병합, 근거 있는 AI 후보, 개인·팀 보고서 일관성을 나누어 검증하는 것입니다. 활성 개발 소스는 `LoadMonitor25/`이며 `LoadMonitor24/`와 `BASELINE.json`은 원본 기준으로 보존합니다.

## 역할

| 이름 | 검토 범위 | 주요 확인 사항 |
|---|---|---|
| `lm25_measurement` | `mine.py`, `collect/`, 시간 산식과 입력 | 구간 중복·월 경계, 투입/가용 MM, 부재, 결측·신뢰도, 100% 초과 로드율 |
| `lm25_workflow` | `core/details.py`, `core/projmap.py`, `judge/refine/agentic/flow.py` | 사용자 지정 우선, 60% 혼재 경계, 병합 금지·크기 상한·결정성, 월·과제별 AI 근거 |
| `lm25_reporting` | `freeze/report_out/export/aggregate/team_report/teamserver.py`, `ui/app.py` | 개인·팀 숫자와 기간 일치, 보고서 경로·수정 시각, 실패·결측 표시 |
| `lm25_quality` | `scripts/`, `.githooks/`, `.codex/`, `LoadMonitor25/tools/`, 회귀·배포 목록 | 린트·훅 성공/실패, TEMP 회귀, 인코딩·무결성·원본 보존, 최종 독립 검토 |

표의 프로그램 경로는 `LoadMonitor25/` 기준이며, 검토 범위가 자동 편집 권한을 뜻하지는 않습니다.

## 호출과 파일 소유권

주도 에이전트가 결과를 통합하고 작업자는 최대 3개까지 동시에 실행합니다. 본체를 포함하면 최대 4개입니다. 역할은 4개지만 전부 동시에 시작하지 않으며, 구현이 끝난 뒤 `lm25_quality`가 독립 검토하도록 순서를 조정합니다.

각 위임에는 목적, 읽을 범위, 편집할 정확한 파일 목록, 완료 조건을 적습니다. 기본은 읽기 전용 검토이고 명시적으로 위임된 파일만 수정합니다. 같은 파일의 소유자는 한 명으로 정합니다. 예를 들어 여러 역할에 걸치는 `flow.py`와 `ui/app.py`는 주도 에이전트가 한 명에게만 편집을 맡기고 다른 역할은 발견 사항을 전달합니다. `FILES.txt` 갱신 역시 한 명이 취합해 수행합니다.

호출 예:

```text
lm25_measurement와 lm25_workflow 서브에이전트를 병렬로 사용하세요.
둘 다 읽기 전용으로 LoadMonitor25/와 docs/PROJECT_CONTEXT.md를 검토하세요.
measurement는 월 경계·가용 MM·중복 구간, workflow는 과제 병합·상위 분류·AI 근거를 맡으세요.
각각 근거 파일:행, 재현 조건, 영향, 수정 제안, 검증 여부를 보고하고 모든 결과를 취합하세요.
```

```text
lm25_reporting에 LoadMonitor25/ui/app.py의 확인된 표시 결함 수정을 위임하세요.
그 파일만 편집하고 TEMP 합성 자료에서 해당 동작을 검증하세요.
완료 후 구현에 참여하지 않은 lm25_quality가 변경 파일과 검증 로그를 독립 검토하세요.
FILES.txt 갱신은 주도 에이전트가 맡으세요.
```

## 검증과 보고

- 실제 수집 자료·개인 설정·로그인 프로필은 테스트에 사용하거나 덮어쓰지 않습니다. TEMP 코드 복제본과 합성 입력으로 검증합니다.
- 사용자 승인 범위에 없는 실제 수집·브라우저·AI 호출·스케줄러·팀 업로드를 시작하지 않습니다. 이미 승인된 작업에는 같은 허가를 다시 요청하지 않습니다.
- 확정 결함과 가설을 구분합니다. 보고에는 우선순위, 근거 `파일:행`, 최소 재현 또는 확인 조건, 사용자 영향, 수정 제안, 수행한 검증과 남은 한계를 포함합니다.
- 정적 검사·합성 회귀·실제 연동 검증을 구분하며, 실행하지 않은 실제 수집·AI·팀 전송 성공을 주장하지 않습니다.
- 구현자와 최종 검토자를 분리합니다. 독립 검토에서 문제가 나오면 구현 담당자가 수정하고 검토자는 해당 수정 범위를 다시 확인합니다.

## 구성 형식

프로젝트의 `.codex/agents/*.toml`에 역할별 파일을 둡니다. 각 파일에는 `name`, `description`, `developer_instructions`만 정의했으며 모델·추론 수준·권한 설정은 부모 설정을 상속합니다. 파일 형식과 상속 규칙은 [공식 OpenAI 서브에이전트 문서](https://learn.chatgpt.com/docs/agent-configuration/subagents)를 기준으로 확인했습니다(2026-09-09).

현재 세션에서 병렬 검토를 실행한 사실과 저장한 역할 파일을 클라이언트가 발견하여 호출한 사실은 별도로 확인해야 합니다. TOML 파싱만으로 역할의 실제 로딩 성공을 주장하지 않습니다.
