1PC 마다 — 수집만클라우드 PC 가 아닌 PC

순서이 PC 에서 할 일
  • 기간이 [올해] · 2026-01-01 ~ 오늘 인지 확인
  • 추가 PC 수집 클릭 (몇 분 ~ 십여 분)
  • 로그 끝에 [수집만] … 분석은 하지 않았습니다. 가 보이면 끝
  • 분석 실행은 누르지 않습니다
클래식 Outlook 이 꺼져 있으면 수집 중에도 Copilot 대체 경로가 자동으로 돕니다. Outlook 을 켜 두면 더 빠릅니다.
수집이 잘 되게 하는 세 가지 (LM22 2차)
① 창 샘플러를 collect\Register-Samplers.ps1 로 한 번 등록(팀즈 샘플러까지면 -Teams; 실행 시간 제한 없음 — 예전의 schtasks 한 줄은 3일 뒤 조용히 멈췄습니다). 샘플러는 키보드·마우스 활동 기준이라 회의실·현장 시간은 캘린더와 수동 기록이 채웁니다.
② 팀즈 표시 이름이 Windows 계정명·owner 와 다르면 config\config.json 의 teamsSelfNames 에 적기 — 없으면 팀즈로 일한 날이 전부 «수신» 이 되어 로드율이 절반으로 나옵니다.
③ 출장·현장·교육은 Outlook 종일 일정(부재중 표시)으로 남기거나 collect\Add-WorkLog.ps1 -Category 출장 -Hours 8 한 줄 — 안 남기면 그날은 0h 또는 부재로 추정됩니다.
git 을 GUI(GitHub Desktop 등)로만 쓰는 PC 는 로그에 «git 실행 파일 없음» 이 뜨면 gitExe 에 경로를 적으세요.

2옮기기PC 를 바꿀 때마다

그냥 복사하면 “사용 중”이라 실패합니다. PC 이동 준비 가 잡고 있는 것을 정리하고 옮길 수 있는지 확인해 줍니다.

순서옮기기 전에
  • PC 이동 준비 클릭 → [확인]
  • 검은 정리 창이 열리고 대시보드는 스스로 닫힙니다
  • 정리 창에 “옮기거나 복사할 수 있습니다” 확인
  [PC 이동 준비] 폴더를 잡고 있는 프로그램을 정리합니다
  대상: D:\LoadMonitor22

  종료할 우리 프로그램이 없습니다 (이미 다 닫혀 있음)

  ============================================================
   이제 이 폴더를 통째로 옮기거나 복사할 수 있습니다.
  ============================================================

   · 다른 PC 로 옮긴 뒤 LoadMonitor22-UI.bat 을 실행하면
     지난 PC 의 수집 데이터는 자동으로 data\추가PC\ 로 보관되고
     분석은 두 PC 를 합쳐 계산합니다.
   · report\upload_pending\ 의 업로드 대기 묶음도 함께 따라갑니다.
■ 여기부터 «복사만» 하는 구간
  • bat 파일을 누르지 않습니다 — UI·팀서버·팀취합 전부
  • 그 폴더를 탐색기로 열어 두지 않습니다
  • 폴더 안 파일을 엑셀·메모장으로 열지 않습니다
  • 쓰는 것은 Ctrl+C / Ctrl+V 뿐 — 폴더 전체
  • 복사는 다음 PC 로만 — USB·공유폴더·메신저 금지 (개인 메일 제목이 들어 있습니다)

옮긴 PC 에서 추가 PC 수집 을 누르면 그때 지난 PC 자료가 data\추가PC\ 로 보관됩니다. 단, 그 PC 가 마지막 클라우드 PC 라면 3장의 분석 실행 을 누르세요.

3마지막 — 클라우드 PC 에서 분석딱 한 번

주의클라우드 PC — Copilot 충돌 피하기
  • 시작 전 팀 채팅방에 “분석 시작합니다” 알리기 — Copilot 창이 떠 있으면 기다립니다
  • 도중에 누가 Copilot 을 써야 하면 중지, 끝난 뒤 다시 실행
  • 내 분석 중에는 Copilot 창을 건드리지 않기
  • AI 정제 는 켜고, «재분석만» 은 끕니다 — 켜면 수집을 건너뛰어 숫자가 조용히 틀립니다

«Agentic AI» 탭은 따로 누를 것이 없습니다 — 분석이 끝나면 자동으로 채워집니다.

LM22 — 하루 상한이 없어졌습니다. 예전의 “하루 최대 13h” 상한을 폐기해 야근·주말 근무가 실제로 일한 시간 그대로 보이고, 그래서 로드율이 100% 를 넘을 수 있습니다(남는 것은 하루 24h 물리 한계뿐). 16h 를 넘긴 날·연차인데 흔적이 있는 날·PC 기록 오류는 잘라내지 않고 «MM 산정 근거» 카드와 리포트 8절의 이상치 표에 날짜별로 표시됩니다 — 수치가 이상하면 그 날짜부터 보세요. 측정 규칙이 바뀌었으니 팀 비교는 전원 LM22 결과끼리만 합니다.
LM22 2차 — 측정 방식 배지·커버리지. 같은 근무라도 PC 전원 정책(절전·항상 켬)·권한· 샘플러 유무에 따라 로드율이 60~130% 로 갈리던 것을 고쳤고, 그날이 샘플러 실측 / PC 하한 / 흔적 창 중 어느 방식으로 계산됐는지와 신뢰도 등급(신뢰 · 주의 · 측정 불충분)이 «MM 산정 근거» 카드·리포트·팀 취합에 배지로 보입니다. «측정 불충분»(PC 기록·샘플러·달력 전부 결측)은 팀 평균·순위에서 빠져 별도 행으로 갑니다 — 4장의 조치대로 수집을 보강해 다시 올리세요. 분모 설정이 팀과 다르면 «산식 설정 상이» 배지가 붙습니다. 2차 이전 결과와 섞어 비교하지 마세요.

4수집이 됐는지 보기분석 뒤

2차부터 수집 현황과 «MM 산정 근거» 카드에 PC 기록 결측 평일(로그 롤오버·힌트 없음 — 흔적 창으로 대신 계산됨), 잠금 이벤트 권한 없음(항상 켜 두는 PC — 창 샘플러 등록 권장), git 실행 파일 없음 (gitExe), 수동 흔적만 있는 평일(팀즈 창 읽기면 teamsSelfNames) 줄이 더 보입니다. 각 줄 오른쪽 조치대로 하고 추가 PC 수집 또는 분석 실행 을 다시 누르면 됩니다.

분석리포트_<기간>.html 결과 파일만으로 만든 한 장 — 팀 취합이 읽는 개인 리포트

개인 리포트는 어디로 가나 — HTML 은 팀 서버로 올라가지 않습니다(서버가 받는 파일 이름 규칙은 그대로). 6장의 공유폴더로 저장 을 쓸 때만 <공유폴더>\개인리포트\ 에 <이름>_분석리포트_<기간>.html 과 <이름>_보고서_<기간>.html 로 함께 복사됩니다(문서형 리포트 .html/.doc 은 복사하지 않습니다).
data\·report\ 폴더는 폴더째 공유 금지 — 메일 제목·회의 제목이 들어 있습니다.

6팀 서버 업로드서버에 닿는 망에서

순서업로드
  • 연결 확인 — 초록이면 닿는 망
  • 팀 서버 업로드 — 끝나면 어느 폴더에 담겼는지 알려 줍니다
  • 못 닿으면 공유폴더로 저장, 또는 닿는 망에서 다시 (묶음은 대기로 남습니다)
  • 끝났으면 클라우드 PC 의 내 폴더는 지우거나 회수 — 내 메일 제목이 들어 있습니다
무엇이 올라가나 — 판정 결과(과제·업무·MM)와 근거 신호 목록입니다. 메일 제목·회의 제목·동료 이름이 포함될 수 있습니다 (excludePathKeywords 로 걸러 둔 개인 폴더 신호는 제외). 사내망 전용.

꼭 지킬 것

요약이 일곱 가지
  • Outlook(클래식)·Teams·Copilot 로그인 유지
  • 기간은 [올해] (1월 1일~오늘) 그대로 — 팀 전체 같은 기간
  • 분석은 마지막 클라우드 PC 에서 한 번만
  • 클라우드 PC Copilot 충돌 피하기 — 알리고 시작, 남의 창 건드리지 않기
  • 이동 준비 → 복사 구간에서는 프로그램 실행 금지 (Ctrl+C / Ctrl+V 만)
  • 리포트 두 파일 저장 · data\·report\ 폴더 공유 금지
  • 분모 설정(standardDayHours·holidays·lunch·dayWindow)은 팀 공통값 그대로 — 개인이 바꾸면 비교가 어긋납니다

문제가 생기면

증상조치
폴더가 “사용 중”이라 안 옮겨진다 PC 이동 준비. 그래도 안 되면 정리 창이 무엇이 잡고 있는지 알려 줍니다 — 대개 탐색기 창.
메일·일정이 0 건 클래식 Outlook 을 켜고 다시 실행 → 그래도 비면 수집 진단.
AI 판정이 안 된다 AI 연결 진단 → 전용 Edge 창에서 로그인 후 다시 실행.
로드율이 낮게 나온다 수집 현황의 노란 항목부터 확인 — 덜 일한 게 아니라 덜 모인 경우가 많습니다.
커밋이 0 건 / 로그에 «git 실행 파일 없음» config\config.json 의 gitExe 에 git.exe 전체 경로(GitHub Desktop·SourceTree 내장 git 은 자동 탐색). 그래도 0 이면 gitRepos 경로 확인.
샘플러가 며칠 뒤 멈춘다 / 상태바에 «샘플러 멈춤» collect\Register-Samplers.ps1 로 다시 등록(3일 실행 제한 없음). 대시보드·분석 시작 때도 자동으로 다시 띄웁니다(autoRestartSampler).
출장·현장·교육 날이 0h 이거나 부재로 잡힌다 Outlook 종일 일정(부재중 표시, 제목에 출장·현장·교육)으로 남기면 8h 로 인정. 없으면 collect\Add-WorkLog.ps1 -Category 출장 -Hours 8 -Date 2026-06-10.
팀즈로 일한 날인데 로드율이 낮다 teamsSelfNames 에 팀즈 표시 이름을 넣고 다시 분석 — «수동 흔적만 있는 평일» 수가 줄어야 정상.
«측정 불충분» / «주의» 배지가 붙었다 PC 기록·샘플러·달력 중 빠진 것이 이유로 적힙니다(배지에 마우스를 올리면 보임) — 4장의 조치대로 보강해 다시 올리기. «측정 불충분» 인 채 팀 표에 올라가면 팀 평균·순위에서 빠져 별도 행으로 갑니다.
«산식 설정 상이» 배지가 붙었다 config.json 의 mm.standardDayHours·lunch·dayWindow·holidays 가 팀 다수와 다릅니다 — 팀에서 정한 값(config.default.json)으로 되돌리고 다시 분석.
“포트를 다른 프로그램이 쓰고 있습니다” 화면이 “예전 버전 LoadMonitor” 라고 한 경우에만 포트 가져오기. 모르겠으면 포트 바꾸기.
팀 화면에 사람이 안 보인다 ‘데이터 읽어오는 곳’ 경로 확인. 못 읽으면 이 PC 의 teamdata 로 전환 버튼이 뜹니다.
업로드했는데 안 보인다 전송 결과의 저장 위치 확인 — 이 PC 에 폴더가 여러 개면 다른 폴더가 받았을 수 있습니다.
