## 0. 한눈에 — 가장 중요한 결정 열 가지

1. 제품은 **LM27(LoadMonitor27)** 이다. 사용자가 처음 쓴 'LM26' 이라는 이름은 별개 프로젝트(`D:\배포\LM26`)와 겹치므로 쓰지 않는다.
2. MS 자료는 **문서화·지원되는 사용자 인터페이스만** 읽는다. Graph·앱 내부 캐시·숨김 폴더·자격 증명·관리자 권한·정책 우회는 쓰지 않는다.
3. 메일·일정은 **로컬 우선**(색인 항상 + COM 정밀) → 원장 **빈칸만** 웹 → 코파일럿은 **존재 증인** → 반입 파일. 첫 성공에서 멈추지 않고 역할을 나눠 키로 병합한다.
4. PC 마다 **능력 탐침**으로 '되는 경로·안 되는 이유'를 숫자와 사유 코드로 남긴다. '불가'는 서로 다른 날 2회 이상(수송 실패 제외)일 때만 확정하고 풀릴 수 있다.
5. **원문은 메모리에만.** 수집기 경계에서 정제하고 열 허용 목록만 저장한다. 코파일럿·팀 업로드 직전에 다시 검사한다.
6. 시간은 **근무 봉투(5분 슬롯 합집합) + 귀속(나누기만)** 두 층이다. Σ귀속 = 봉투를 날마다 검사하므로 병행 업무로 MM 이 부풀지 않는다.
7. **코파일럿은 시간·MM 을 계산하지 않는다.** 이름·분류·요약·관계 서술만 한다. 날짜만 아는 신호와 코파일럿 요약은 시간 근거가 아니다.
8. 업무 계층은 **업무 영역 5종(+미분류) → 과제 → 역할 업무 → 단위 업무**, 직교 축 **업무 유형**.
9. PC 별 **불변 세그먼트를 폴더째 옮긴다.** 다른 PC 자료는 건드리지 않고, 두 번들을 합쳐도 결과가 같다.
10. 팀 서버 기본 주소 **`http://10.115.147.68:9310` 은 바꾸지 않는다**(바꾸는 옵션만 둔다). 사람이 하는 일은 로그인 한 번과 확인 질문 응답뿐이다.

## 2. 사용자 운영 원칙 — 어기면 안 됨 (결정 §1)

- 실명·계정·이메일·사내 코드네임을 코드·문서·샘플·코파일럿 프롬프트에 넣지 않는다. 자리표시자(홍길동·과제A 등)를 쓴다.
- 사용자를 대신해 로그인하지 않는다(브라우저 로그인은 사람이 한 번). 비밀번호·토큰을 다루지 않는다.
- 다른 사용자에게 수동 조작(재분석 버튼·zip 풀기 등)을 요구하는 설계를 하지 않는다. 문제는 스스로 복구한다.
- 팀 서버 기본 주소 `http://10.115.147.68:9310` 은 **절대 바꾸지 않는다**(사용자 지시). 화면·설정에서 IP·포트를 바꾸는 **옵션**만 둔다.
  - 같은 호스트에 LM24 서버(9310)가 돌 수 있으므로, LM27 클라이언트는 업로드 전에 `/api/hello` 로 상대가 LM27 팀 서버인지 확인한다.
  - LM27 서버는 포트가 점유되어 있으면 원인(프로세스 이름)과 대체 포트를 보여 준다.
- 커밋은 즉시 푸시하고 한국어로 자세히 쓴다. 편집 직후 검사 훅과 lint 관문을 필수로 둔다.

## 4. 큰 구조 (결정 §3)

```text
수집(PC 마다) → 운반 번들(폴더째 이동) → 정규화·정제(저장 전) → 병합(PC·경로 중복 제거)
→ 시간 추론(근무 봉투 + 단위업무 + 귀속) → 분류(레지스트리 규칙 → 코파일럿)
→ 분석(워크플로우·리뷰·동료·온톨로지·agentic) → 개인 보고서 → 팀 업로드(집계·라벨만)
→ 팀 서버(취합·팀 보고서·간트 드릴다운)
```

- **PC 상주 부분**(샘플러·이벤트 수확기·로컬 원장)은 `%LOCALAPPDATA%\LoadMonitor27\agent\` 에, **운반 번들**은 프로그램 폴더의 `data\` 에 pc_id 별 불변 세그먼트로 둔다. 다른 pc_id 자료는 절대 이름을 바꾸거나 옮기지 않는다. 코파일럿 Edge 프로필은 번들 밖(`%LOCALAPPDATA%`)에 둔다.
- **계정 단위 자료**(메일·팀즈·일정)의 '기간 전체 백필'은 클라우드PC(또는 백필 담당 PC)에서 한 번 한다. PC1·PC2 는 그 PC 사용이력과 로컬에서 되는 경로만 맡는다. 겹치는 것은 `msg_key` 로 병합한다.
- MS 수집은 '첫 성공에서 멈추는 사슬'이 아니라 **역할 분담 + 키 병합 + 일자 × 출처 커버리지 원장**이다.
- PC 마다 **능력 탐침**(Outlook 클래식/새, Office 판·C2R, COM 붙기, 색인의 Outlook 항목 수, Teams 클래식/새, 창 UIA 텍스트 수, Edge 원격 디버깅 정책, 웹 로그인 상태, 코파일럿 커넥터)을 먼저 돌려 '되는 사람/안 되는 사람'을 숫자로 설명한다.
- '불가'는 **서로 다른 날 2회 이상 + 수송 실패가 아닐 때만** 확정하고, 탐침 값이 바뀌면 해제한다.

## 6. 시간 모델 (결정 §5 + v2 §10.2·§10.3)

### 6.1 기본 원칙 (결정 §5)

- **두 층.** (a) 근무 봉투 = 사람별 5분 슬롯의 합집합(모든 PC·경로), 결정적 로컬 계산. (b) 귀속 = 봉투 슬롯을 단위업무에 나누기만 한다(Σ귀속 = 봉투, 날마다 assert). 어느 업무에도 안 붙은 슬롯은 '근무 중 미분류' 버킷.
- **리드타임(의뢰~보고 경과)과 투입 시간을 나눈다.** 간트 막대(첫~마지막 근거)는 투입이 아니다.
- **슬롯 꼬리표.** 정규(평일 표준창, 기본 09~18·점심 12~13, 개인 설정) / 연장(평일 창 밖) / 야간(22~06) / 휴일(주말·공휴일).
- **1MM = 8h × 그 달 평일(공휴일 제외).** 1MM 초과를 허용하고, 이상치는 표시하되 자르지 않는다.
- **퇴근 후·주말**은 능동 산출 신호(발신 메일·팀즈 발신·문서 저장·커밋·상용 프로그램 능동 사용)가 있을 때만, 그 앵커들을 잇는 구간(+pad)으로 인정한다. 늦게 시작해 새벽에 메일을 보낸 경우는 연속으로 인정한다. PC 없이 밖에서 보낸 메일은 최소 크레딧(+스레드 연결).
- **코파일럿은 시간·MM 을 계산하지 않는다.** date-only·코파일럿 요약 신호는 시간 근거가 아니다.
- **근거 없는 시간을 만들지 않는다.** 추정치는 신뢰도 등급과 출처 꼬리표를 달고, 낮은 등급은 확인 큐로 보낸다.

| 배경 연산(솔버) | 사람 증거(전경·입력·발신)가 있는 슬롯에서는 귀속 근거로 쓰지 않는다. '기계 시간' 열(MM 미포함)로 따로 보인다. 사람 증거 없는 제출~대기 슬롯만 상한 규칙 |
| 사적 사용 차감 | 봉투 계산의 **마지막 단계**에서 사적 앱·사이트 전경 구간을 뺀다(하한·다리·크레딧을 만든 뒤). 차감량은 설명 원장에 남긴다 |
| 무증거 슬롯 배분 | 직접 증거 분에 비례, 증거가 없으면 '근무 중 미귀속' 버킷. 균등 배분·과제 비중 배분은 폐기 |
| 미등록 외근 후보 | 평일 PC 기록 없음 + 발신이 넓게 분포 + 달력 외근 단서 → 흔적 창 기본, 표준일 상한, 확인 큐(응답 없으면 흔적 창만) |
| 파라미터 | 휴면 K일·pad·다리·단독 발신 크레딧 등은 설정 레지스트리에 '미보정' 표식. 수동 업무 기록을 정답 세트로 격자 보정하는 도구(calibrate)를 둔다 |
| 간트 | 옅은 **리드타임 띠** 위에 진한 **투입 밀도 칸**, 행 끝에 투입 h·병행도·리드타임. 막대 = 단위업무 구간. 행 계층 기본 = 담당자 → 업무 영역 → 과제 → 역할 업무, 피벗 토글로 업무 영역 → 과제 → 역할 → 담당자. 막대·행 클릭 → 그 사람의 그 업무 워크플로우 |

### 6.3 시간대·달력 (결정 §10.3)

- 동봉 파이썬에는 tzdata 가 없다(`zoneinfo.ZoneInfo('Asia/Seoul')` 실패 실측). 수집 시점에 `ts_utc` + 그 순간 오프셋을 저장하고, 분석 근무 시간대는 설정 기본 +09:00(또는 ctypes `GetDynamicTimeZoneInformation`). **`zoneinfo.ZoneInfo` 사용 금지(관문).**
- 공휴일은 내장 표를 그대로 옮기지 않는다(LM24 2026-09-28 오류 — 추석 9/24~26, 토요일 겹침은 대체공휴일 없음). 공고 근거 URL·확인일을 단 `calendar.json` 을 쓰고, 팀 서버 배포본이 우선이며 내장은 확인된 해만 둔다. 관문: 2026-09 평일(근무일) 20일, 2026-10 20일(10/5 개천절 대체·10/9 한글날).
- 1MM 분모 기본 = 공휴일 제외 평일 × 8h. 설정 `mm.denominator` 로 '달력 평일 전체'를 고를 수 있고 화면에 분모 정의를 표시한다 — **사용자 확인 항목**(§15 UD-01).

## 7. MS 수집 경로 (결정 v2 §10.1)

사용자 문장 "로컬색인을 우선적으로, 그다음 코파일럿"을 따른다.

| 순서 | 경로 | 역할 |
|---|---|---|
| 1 | 로컬 색인(Windows Search) | **항상** 돌려 교차검증 |
| 2 | 클래식 Outlook COM | 분 단위 정밀 원장 |
| 3 | 웹(OWA) — 백필 PC | 원장 **빈칸만**. 일정은 기간 전체, 보낸 편지함은 항목을 열어 분 단위, 받은 메일은 날짜만(= 존재·건수 증거) |
| 4 | 코파일럿 | 빈칸의 **존재 증인**(시간 근거 아님) |
| 5 | 반입 파일(EML·CSV·ICS) | 정식 대체 경로 |

- **COM 은 두 단으로 나눠 읽는다.** A단 = 비보호 열(제목·시각·폴더·크기·MessageClass·Categories·ConversationID 등), B단 = 보호 열(발신 주소·수신자·본문·PropertyAccessor·CurrentUser). B단은 탐침이 Object Model Guard 통과를 확인한 PC 에서만, 시간 제한이 있는 하위 프로세스로 읽는다. 실패를 삼키지 않고 사유 코드(`R-OMG`)로 남기며, 행을 통째로 버리지 않는다.
- **모든 메일 폴더를 재귀**한다(하위 폴더·보관 사서함 포함, 삭제·정크 제외). 캐시 동기화 기간 밖·새 Outlook 기간·색인 비활성 일자는 '0건'이 아니라 **구조적 공백**(out_of_horizon·blocked)으로 원장에 남긴다.
- **팀즈**: teams.uia(로컬, 실시간) + teams.web(백필) + Teams '놓친 활동' 알림 메일을 '팀즈 수신 존재' 간접 증거로 라벨(시간은 상한으로만). 앱 내부 캐시·알림 DB·숨김 폴더는 **영구 제외**.

## 8. 코파일럿 (결정 §6 + v2 §10.1)

- 클라우드PC **한 곳에서만** 로그인·사용한다.
- 브리지 5계층: L0 세션 · L1 전송 · L2 교환(rid 봉투·검증·상태 분류) · L3 배치 실행기(패킹·반분·누락 재질의·저널·재개·예산) · L4 단계 프롬프트.
- 입력 기본 8,000자·답 5,000자(보정 프로브로 실측 갱신). 완료 판정은 fail-closed. 치명 실패는 2-strike + 조건 폴링. 항목 단위 저널 커밋과 재개.
- **수동 붙여넣기 경로를 대체 경로로 정식 지원**한다(원격 디버깅 정책이 막힌 PC).
- 전송 직전 개인정보 게이트: 같은 정제기로 재검사, 잔여 PII 행 제외, 건수만 감사.
- v2 탐침: 계정 등급(Basic/Premium)·Work 탭·웹 근거 토글. Basic 이면 메일·팀즈 증인 경로를 끄고(`R-NOLIC`) 분석 왕복은 '붙여넣은 정제 텍스트' 모드로 한다. 웹 근거가 켜져 있으면 전송 직전 재검사를 강화한다.

## 9. 정제 — 필터 (결정 §7)

- 수집기 경계에서 메모리 안 정제 → **열 허용 목록만 저장**(원문 비저장).
- PII 유형 토큰 치환: 주민·외국인등록·카드(Luhn)·전화·사업자(체크섬)·여권·계좌(문맥)·이메일 로컬파트·IP.
- 금액은 `[금액]`(공학 단위 오탐 방지). 고객사는 사전 가명화(설정). 이름은 키 기반 HMAC 가명화.
- 광고 점수: 헤더·'(광고)' 표기·수신거부·외부 무왕래 도메인.
- 사적 점수(공사 구분): 사적이면 본문 삭제 + 시간 근거 제외 여부 규칙.
- 정제 규칙 버전·건수 감사. 합성 양성/오탐 미끼 회귀 말뭉치를 관문으로 둔다.

## 11. 보고서·분석 (결정 §8 + v2 §10.5)

- **개인 보고서**: 영역/과제/역할/단위 계층 워크플로우, 주간·월간 리뷰, 같이 일한 동료(가명 키, 표시명은 로컬에서만), 온톨로지(과제–역할–단위–문서–앱–동료 관계 그래프), agentic 매칭(카탈로그 × 단계 유형) + 새 니즈, 워크플로우 단계별 서브에이전트 도입 적합성 검토, 시간·MM·초과(연장/야간/휴일) 대시보드.
- **팀 보고서**: 영역별 리소스(MM) 투입, 역할/단위·유형 분포, agentic 매칭·니즈 취합, **담당자별 영역/과제/역할 다월 간트** — 막대 클릭 → 그 사람의 그 업무 워크플로우 상세.
- **디자인**: LM20 언어(상단 가로 pill 메뉴, 바탕 #f2f4f7, 강조 #2a78d6, KPI 카드, 표 + 펼침 상세), 본문 16px·표 14px, 외부 CDN 금지(로컬 SVG), 도표 중심 + 근거 드릴다운. 관측과 추정을 시각적으로 구분.
- **온톨로지**: 닫힌 관계 어휘(의뢰함/보고함/산출함/사용함/함께함/선행함/같은문서/같은과제), 가중치 = 공유 근거 수·슬롯 h, 연관도 = 공유 문서·동료·앱 Jaccard + 시간 선후, 로컬 SVG 과제 중심 방사형(상위 N, 나머지 '기타'). 코파일럿은 관계 서술만.
- **서브에이전트 검토**: 반복성(같은 역할 업무 단위업무 주기)·디지털 입출력 비율·정형 입력(첨부 확장자 분포)·책임도(보고 대상 등급)·검증 가능성을 원장 수치로 계산. 코파일럿은 근거 문장만.
- **agentic 카탈로그** = 팀 레지스트리 `agents[]`(LM24 `agentic_tasks.json` 의 {axes, tasks} 구조 + 입력·출력·적용 단계 필드). 저장소 기본값은 중립 예시만.

## 15. 사용자 확인이 필요한 결정

### 15.1 읽는 법

- 각 명세의 '사용자 확인이 필요한 결정'·미결 중 **사용자·팀장·정보보안·IT 가 정할 것**을 한 표로 모았다. 출처: W §11.2 D1~D14, H §17.2 D-H1~D-H10, R §14 R-Q1~R-Q15, P §21, B §16, TAB §11, CM §16, CP §17, C(설정 항목), CONTRACT §12.1 U-1~U-14. 같은 질문은 한 행으로 합쳤다.

- 실측·설계 세부·오케스트레이터가 정할 미결은 §16 에 따로 적었다.
- ★ = 미보정 값(실자료 보정 전).
