1. 먼저, 분명한 결론

확정된 코드 결함

수집·날짜·병합에 문제가 있었습니다.

이어서 읽을 위치가 사라지거나, 다른 연도로 분류되거나, 최신 본문이 옛 본문으로 바뀌는 경우를 합성 입력으로 재현했습니다.

구조적 한계

화면 조회로 전체 확보를 보장할 수 없습니다.

화면에 올라오지 않은 대화, 동기화되지 않은 메일, 접근 권한 밖의 자료는 보이지 않을 수 있습니다. AI가 이 빈칸을 사실로 복원하지 않습니다.

아직 확인하지 못함

사용자 PC의 0건 원인은 미확정입니다.

다른 PC의 현재 로그인·정책·화면·실행 원인표를 직접 대조하지 못했습니다. 이번 수정이 그 PC에서 성공했다는 뜻은 아닙니다.

테스트 통과 ≠ 모든 메일·채팅 수집 성공.
이 보고서의 검증은 재현된 코드 동작을 검증합니다. 실제 계정에서는 같은 기간의 원본 건수·본문·계정을 대조해야 합니다.

일반 Edge나 Teams 앱에 로그인돼 있어도 LM의 전용 Edge 프로필이 로그인돼 있다는 뜻은 아닙니다. 새 풀패키지를 별도 폴더에 풀면 기존 설정·데이터·프로필이 자동으로 옮겨지는 것도 아닙니다.

클래식 Outlook의 완료된 오래된 월은 매번 전부 재조회하지 않습니다. 늦게 동기화된 과거 메일은 별도 재확인이 필요합니다. 이는 이번 검사로 전체 동기화가 보장됐다는 뜻이 아닙니다. Windows 색인은 메타데이터와 최대 20,000행 범위이며 페이지 이어받기가 없습니다. 웹 일정은 화면 이동 실패를 차단했지만 성공 화면의 표시 주차·연도 일치까지 검증하지는 않습니다.

6. 데이터 품질을 세 가지로 나눠 설명해야 합니다.

① 확보 범위

어느 계정·기간·폴더·대화에서 얼마나 읽었나?

Graph 페이지 완료도 승인된 범위의 완료입니다. 다른 사서함·보관함·권한 밖 대화까지 뜻하지 않습니다.

② 문맥 깊이

제목만 있나, 본문 일부인가, 평문 전체인가?

Graph·COM·선택 파일은 확보한 전체 평문을 별도 보관합니다. 분석은 기본 4,000자, AI 요청은 신호당 800자 발췌입니다. 웹은 화면에서 확인된 범위입니다.

③ 분석 신뢰

관측된 근거인가, 추정·요약인가?

AI는 전달된 근거로 업무를 정리합니다. 못 읽은 채팅의 새로운 업무·진행 방향을 이미 알고 채워준다고 설명하면 안 됩니다.

원문·시각·식별자사실 근거
→
업무 분류·관련성규칙 + AI 해석
→
투입 추정·후보 검토누락과 신뢰도를 함께 표시

메일·채팅 건수는 근무시간이 아닙니다. 적게 수집됐다고 업무가 없었다고 결론 내릴 수 없고, AI가 연결한 업무 MM 전체를 절감 가능한 시간으로 볼 수도 없습니다.
