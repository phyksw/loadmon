  • 전달비: 복원한 영상의 무늬 선명도 ÷ target 영상의 무늬 선명도. 1.0 이면 같다. 합격 범위는 0.9–1.1.

1. 지난 보고 이후 한 일

요약
  1. 모서리 PSF 추정을 막던 큰 원인은 동공(빛이 지나는 구멍) 모양이었다. 모양을 물리 법칙 두 개로 정했다 (한 방향은 주광선 각도의 cos, 다른 방향은 주변 광량비). 다만 이것으로 모서리가 다 풀린 것은 아니다. 공식 측정에서 코너 선명도는 아직 안 맞는다 (3절).
  2. slim 과 target 을 같은 방법으로 추정했다 (이름 R4). 빠른 시험에서 모서리 선명도 비가 0.49 에서 1.02 로 올랐다 (1.0 이 target 과 같음). R4 를 모서리에만 썼을 때의 값이고, 화면 전체에 쓰면 0.86 이다.
  3. 선명도 지표를 '경계 MTF50 비'에서 '무늬 전달비'로 바꿨다 (11-10 승인). 경계 지표는 링잉(가짜 테두리)에 속기 때문이다.
  4. 이 방법을 PB-A v2 로 합쳐서 공식 측정(반복 2)을 돌렸다. PB-A v2 는 PSF 전체를 R4 로 추정한다.

4. 평균이 가린 것 ② 왜곡

요약
  1. relaxed 의 G1 0.225 px 는 대부분 4배 줄인 미리보기에서 나온 값이다. 참 상태를 넣어도 미리보기는 0.17 px 이 나온다. 그래서 이 실패는 복원 오차라기보다 재는 방법의 한계로 본다 (미리보기에서만 크게 나오는 까닭은 아직 확인하지 않았다).
  2. relaxed 는 원해상도로 보면 화면 80 % 위치까지 0.05 px 이하로 잘 맞는다. 6P 는 원해상도에서도 60 %·80 %·가로 80 % 위치가 0.15–0.25 px 로 한도를 넘는다.
  3. relaxed 의 진짜 문제는 코너다. 95 % 위치에서 0.76 px 이고, 5대 모두 0.58–0.93 px 이다. 특정 렌즈가 아니라 공통 문제다.
  4. 이 코너 오차는 '재지 않은 바깥을 짐작해서' 생긴 것이 아니다. 채점된 점은 모두 측정 반경(중심에서 화면 모서리 끝까지 거리의 97.3 %) 안쪽에 있다. 원인은 아직 모른다.
  5. 측정 반경 바깥의 맨 끝 코너는 채점되는 점이 하나도 없다. 평가가 그곳을 보지 않는다.

5. 평균이 가린 것 ③ 빠진 1대, 빗나간 추정

요약
  1. relaxed 5번 대는 PB-A 의 기하 추정이 크게 빗나갔다 (3.77 px, 나머지 5대는 0.12–0.37 px).

  3. 6P 에도 빗나간 대가 있다 (1번, 1.29 px). 그런데 이 대는 복원 결과가 다른 대와 같다.
  4. 그러니 고치기 전에 'PB-A 오차 지표가 복원 품질을 제대로 대변하는가'부터 확인해야 한다.
  • 실패 메시지: supersample S=5 aliases the OTF below g_max=2.371 … use S >= 6. 빗나간 기하가 국소 확대율을 키운 것으로 추정한다 (확대율이 저장돼 있지 않아 직접 확인하지 못했다).
  • 정답 기하를 같은 형식에 담으면 이 대도 0.004–0.017 px 로 정상이다. 형식의 한계가 아니라 추정 실패다. 원인은 아직 모른다.
  • 6P 1번 대가 멀쩡한 이유 후보: 오차가 큰 구역을 평가가 거의 재지 않는다 / slim 과 target 추정의 공통 오차가 서로 상쇄된다 / 두 지표의 계산식이 다르다.

8. 6P 는 어디까지 되나

요약
  1. 정답 PSF 를 주면 6P 도 원리상 target 만큼 선명해질 수 있다 (계산값).
  2. 대신 그만큼 세게 복원해야 한다. 화면 60–95 % 위치의 방사 방향에서 노이즈가 약 3.7배 커진다 (SNR 11–12 dB 손실). 같은 위치·방향에서 relaxed 는 0.7–0.8배다.
  3. 화면 중심에서는 반대다. relaxed 가 약 2.5배, 6P 가 약 1.4배 커진다.
  4. 가장 큰 값끼리 보면 relaxed(중심, 약 2.5배)가 6P(외곽, 약 3.7배)보다 작고, 공식 측정의 위치별 선명도도 relaxed 가 낫다 (3절). 그래서 relaxed 를 1순위로 둔다. 6P 는 학습 요소가 필요한 후보로 남긴다.

9. 왜 막혔나, 그리고 안 해 본 방법

지금 막고 있는 것
  1. PSF 를 담는 형식의 한계. 정답 PSF 를 지금 형식에 담기만 해도 오차가 0.06–0.08 이다. 허용 오차는 0.02–0.03 이고, 실제 추정은 0.23–0.28 이다.
  2. 두 번 추정해서 나눈다. slim 과 target 을 따로 추정하므로 두 오차가 합쳐진다.
  3. 코너. 측정 범위 안인 반경 91–97 % 지점에서 이미 0.6–0.9 px 어긋난다. 차트 네 귀퉁이의 작은 점은 PB-A 가 아직 쓰지 않는다.
  4. 추정이 6대 중 1대꼴로 빗나간다 (5절).
  5. 아직 확인하지 못한 것: 정답 PSF 를 넣으면 위치별 전달비가 정말 1.0 이 되는가. 안 된다면 PB-B 연산자도 한계다.

지금 방식 (R4)

① slim 과 target 을 따로 촬영렌즈마다 초점면 5장
↓
② 렌즈마다 PSF 모델을 따로 추정모델에 담는 과정에서 오차가 생긴다
↓
③ 두 모델을 나눠서 전달 커널 계산두 추정의 오차가 합쳐진다

직접 방식 (제대로는 아직 안 해 봄, 1순위 후보)

① 같은 차트를 slim 과 target 으로 촬영초점 맞은 1장씩이면 된다
↓
② 기하 보정으로 두 영상을 겹친다지금 있는 기하 보정을 그대로 쓴다
↓
③ 커널을 영상에서 바로 계산'slim 영상에 어떤 커널을 걸면 target 영상이 되는가'를 위치별 최소제곱으로 푼다. PSF 모델을 거치지 않는다
  • 기대: 모델 오차와 두 추정의 합성이 없다. 남은 미세한 어긋남과 밝기 비까지 커널이 흡수한다. 계산이 빠르다 (지금 PB-A 는 대당 약 6분).
  • 주의: 두 촬영의 차트 자세 차이를 먼저 없애야 한다. 보정한 초점·거리에서만 맞는다. 6P 의 노이즈 증폭은 그대로다. 위치 사이 보간은 따로 검증해야 한다. 또 선명도 쪽 결과물이 '렌즈 상태'가 아니라 'slim → target 한 쌍의 전달 커널'이 된다. 렌즈 상태 형식에 쌍 항목을 새로 넣어야 한다.
  • 참고: 비슷한 간이 계산은 빠른 시험에서 한 번 했다 (이름 R3, relaxed 공칭 렌즈 1대). 같은 점 패널을 slim 과 target 으로 찍어 스펙트럼의 비를 바로 구한 것인데, 전달 오차가 R4 보다 컸다 (80 % 위치 부근 0.98 대 0.70, 모서리 0.43 대 0.28). 제안한 방식은 기하 보정 뒤 영상에서 커널을 최소제곱으로 푼다는 점이 다르다. 그래도 '직접 구하면 바로 좋아진다'는 근거는 아직 없다.
  • 천문 영상 차분에서 쓰는 방식이다 (Alard & Lupton 1998, Bramich 2008). 지금 방식(R4)을 뼈대로 두고 쌍 영상으로 잔차만 고치는 혼합형도 후보다.
  • 설계 정보를 쓰는 방법 (설계 곡선을 사전 지식으로) 은 계획에는 있었지만 3회 반복 동안 보류됐다. 설계 곡선은 화면 끝까지 알려져 있어서 코너 기하에 도움이 될 수 있다 (코너 오차의 원인을 먼저 확인해야 한다).

10. 학습 결과

요약
  1. 3회 반복 동안 학습시킨 AI 요소는 없다. 왜곡·밝기·PSF 모두 물리 모델을 데이터에 맞춘 것이다.
  2. relaxed 와 노이즈 OFF 조건에서는 올바른 선형 커널이면 충분하다. 그래서 물리 모델을 먼저 맞추는 순서는 맞다.
  3. 학습이 필요한 곳은 6P (정보가 모자람) 와 노이즈 ON 이다. 물리 PSF 가 안정된 뒤에 시도한다.

11. 다음 단계 (제안)

순서
  1. 평가 누락 수정. 복원이 실패한 대를 실패로 집계하고 반복 2 를 다시 집계한다. 위치별 표를 진단표로 추가한다. 게이트 정의와 한도는 바꾸지 않는다.
  2. A. 상한 확인 (개발용 1–2대). 정답 PSF 를 넣었을 때의 위치별 표를 만든다. PB-B 연산자의 한계와 PSF 형식의 한계를 가른다.
  3. B. 직접 방식 (같은 대). 지금 방식·A 와 같은 위치별 표로 비교한다.
  4. C. 코너 기하. 먼저 원인 두 가지를 개발용 대에서 확인한다: 반경 90 % 부근부터 왜 나빠지는가, PB-A 지표가 나쁜 대의 복원은 왜 정상인가.
  5. 도구 수정 (12절).
이 PC 에서 할 수 있는 것
이 PC 에는 렌더 데이터와 Python 3.11 환경이 아직 없다. 1번(평가 누락 수정)은 이미 있는 결과 파일을 다시 집계하는 일이라 렌더 데이터 없이 될 것으로 본다 (확인 전). 다만 Python 3.11 환경은 먼저 만들어야 한다. A·B·C 는 원본 PC 의 렌더 데이터 약 16.9 GB 가 있어야 한다.
같은 이유로 이 보고서에는 공식 측정 후보(v2)의 복원 영상이 없다. 1·8절의 그림은 빠른 시험에서 저장해 둔 조각이다. 렌더 데이터가 오면 위치별 복원 조각을 추가할 수 있다.

12. 도구에 남은 문제

  • 평가기가 복원이 실패한 대를 '완료'로 적고 평균에서 뺀다. 실패로 집계하거나 '불완전'으로 표시해야 한다.
  • 자동 요약(src/loop/report.py)이 옛 이름(estimated@v1)을 써서 v2 결과와 봉인 판정이 요약에서 빠진다.
  • 봉인 시험 단계에 'val 채택 뒤에만 실행' 조건이 없다.
  • A6(PC 안전) 판정이 예전 작업 기록까지 훑는다. 이번 반복만 보도록 고쳐야 한다. 다만 고쳐도 A6 는 실패로 남는다. 이번 반복의 PB-A v2 val 평가 작업 7건이 12분 한도를 넘었기 때문이다 (12.3–13.1분). 이 평가 작업을 더 짧게 나눠야 한다.
  • PB-B 는 OTF 표본 검사에 걸리면 그 대의 원해상도 복원을 전부 포기한다. 더 촘촘한 표본으로 다시 시도하는 길이 필요하다.
