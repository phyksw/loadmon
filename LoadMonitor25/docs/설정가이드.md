# LoadMonitor25 설정 가이드

모든 설정은 **`config\config.json`** 한 파일입니다. 메모장으로 열어 고치면 되고,
저장 후 다음 [분석 실행]부터 반영됩니다(서버 재시작 불필요).

JSON 규칙 세 가지만 주의하세요.
- 문자열은 큰따옴표 `"..."`
- 항목 사이에는 쉼표 `,` (마지막 항목 뒤에는 쉼표 없음)
- 경로의 백슬래시는 두 번 `\\` → `"D:\\작업\\설계"`

---

## 1. watchFolders — 가장 중요 (파일·Recent 소스)

산출물(설계·문서·코드)이 실제로 저장되는 폴더를 나열합니다.
여기 없는 폴더의 작업은 잡히지 않습니다.

```json
"watchFolders": [
  "D:\\작업",
  "C:\\Users\\홍길동\\Documents\\프로젝트",
  "\\\\서버\\팀공유\\설계자료"
]
```
네트워크 드라이브도 됩니다(느릴 수 있음). 하위 폴더까지 자동으로 훑습니다.

- **공유·동기화 폴더**(`\\서버\…`, OneDrive/SharePoint 동기화 라이브러리)를 넣으면 동료가 저장한
  파일도 mtime 이 내려옵니다. 수집기가 `author`(Office 문서의 마지막 수정자, 그 외는 파일 소유자)를
  함께 적고, 분석은 `owner`·Windows 계정명·`teamsSelfNames` 와 다른 사람의 파일을 **'파일(타인)'**
  (과제 맥락용, 시간 근거·PC 하한 게이트 아님)으로만 남깁니다. 신호 출처 카드의 '제외 — 타인 저장 파일'
  에 건수가 보입니다.
- `.venv`·`site-packages`·`node_modules`·`__pycache__`·`.git`·`build`·`dist` 같은 패키지·빌드 폴더는
  기본으로 빠집니다(`excludePackageDirs: true`). pip/npm 설치 한 번이 수천 건의 '파일(코드)' 로 잡히던
  왜곡 방지 — 굳이 잡고 싶으면 `false`.
- 기본 확장자(`watchExtensions`)에 매크로 Office(`.xlsm .xlsb .pptm .docm`)·한컴 `.hwpx`·Visio `.vsdx`·
  LabVIEW `.vi`·OneNote `.one`·Outlook 항목 `.msg` 가 추가됐습니다. 예전 config.json 을 그대로 쓰는
  사람은 목록에 손으로 보태세요.
- 실행 때마다 관측한 (파일, 그때의 mtime) 은 `data\files\files_history.csv`·`recent_history.csv` 에 400일간
  누적됩니다 — 같은 문서를 여러 달 고쳐도 앞 달의 저장 근거가 남습니다(매월 실행할수록 이득).
- `author` 는 Office(OOXML) 문서의 `lastModifiedBy`, 공유·동기화 폴더의 그 밖의 파일은 NTFS 소유자로 채우고
  로컬 폴더의 PDF·CAD 등은 비웁니다(구분 불가·ACL 비용 회피, 큰 공유 폴더는 90초 예산). Recent 에는 `src`(lnk|mru)·
  `target_mtime`(대상 파일의 현재 수정 시각) 열이 생겨 **열람만 한 문서**(열람 시각이 수정 시각보다 늦음, Outlook 첨부
  캐시)를 '파일(열람)' 로 구분합니다 — 첨부 1건을 열어 본 날이 하루 9h 가 되던 과대 방지(§9 `viewCountsAsActive`).
  로그인된 Office 의 `User MRU` 키까지 읽어 M365 계정 PC 에서 MRU 가 0건이던 것도 고쳐졌습니다(`[recent] mru keys=N`).

## 2. excludePathKeywords — 필수 (개인정보 방어선)

경로·파일명에 이 키워드가 있으면 수집·리포트·AI 프롬프트 **전부에서 제외**됩니다.
본인 개인 폴더 이름을 반드시 추가하세요.

```json
"excludePathKeywords": ["개인", "가족", "이력서", "다운로드", "temp", "본인폴더명추가"]
```

매칭 규칙(파일·Recent·git 수집기와 분석이 같은 규칙):
- 경로 전용 토큰 `temp` `downloads` `임시` `다운로드` 는 **폴더 이름이 정확히 그것일 때만** — `Temperature_Test`,
  `temp_sensor`, `template` 폴더는 빠지지 않습니다(예전엔 부분 문자열이라 통째로 사라졌습니다).
- 영문 키워드는 단어 경계(`temp` ⊄ `attempt`), 한글은 부분일치(`개인` ⊂ `개인자료`).
- 무엇이 빠졌는지는 수집 로그의 `[files] 제외: temp 12폴더 340건` 줄과 `data\files_excluded.json` 에 남습니다.
  기대한 폴더가 안 잡히면 여기부터 보세요.

## 3. gitRepos — SW 개발 시간 회수 (선택)

```json
"gitRepos": ["D:\\src\\projA", "D:\\src\\projB"]
```
어디에 저장소가 있는지 모르면 자동 탐색이 찾아서 config에 넣어줍니다:
```
python collect\Get-GitActivity.py --scan D:\src
```

**git 실행 파일 요건** — 수집기는 `git.exe` 를 PATH → Git for Windows(`Program Files\Git\cmd`) →
GitHub Desktop → SourceTree → Visual Studio 내장 git 순으로 찾습니다. 어디에도 없으면 `[git] git 실행 파일
없음 — 커밋 신호 수집 불가` 를 찍고 그 단계를 **실패로 기록**하며 찾아본 곳을 `data\git_source.json` 에
남깁니다([수집 진단]·`python 자가점검.py` 도 같은 탐색 결과를 보여 줍니다; 기존 `git_commits.csv` 는 덮어쓰지
않습니다). 예전에는 이 경우 조용히 '커밋 0건'(단계 OK) 이라 GUI git 사용자만 커밋 신호가 통째로 빠졌습니다.
자동 탐색이 못 찾으면 전체 경로(또는 설치 폴더)를 적으세요:
```json
"gitExe": "C:\\Users\\홍길동\\AppData\\Local\\Programs\\Git\\cmd\\git.exe"
```
현재 체크아웃된 브랜치뿐 아니라 **모든 로컬·원격 브랜치**의 내 커밋을 로컬 시각으로 모읍니다
(`git_commits.csv` 의 `branch` 열). 저장소 경로에도 §2 의 제외 규칙이 걸립니다.

## 4. 창 샘플러 — 상시 가동 (선택, 키보드·마우스 활동 기준)

1분마다 "지금 어떤 창에서 일하는지"와 무입력 시간을 기록합니다. IDE 감지로 SW 개발 시간이
정확해지고, 샘플러가 덮은 시간은 PC 하한 대신 **실측**이 쓰입니다.

> 샘플러가 재는 것은 **키보드·마우스 활동 시간**입니다. 자리 토론·전화·즉석 회의처럼 캘린더에 없는
> 대면 업무는 무입력이라 빠지므로, 가동 창 안의 60분 이하 공백은 근무로 잇습니다
> (`mm.samplerGapBridgeMin`, 0 이면 예전처럼 버림). 샘플러를 켜기 전·죽은 뒤의 PC 가동 구간은 예전처럼
> 하한으로 채우고(비율 문턱 없음), 같은 창 제목을 계속 보고 있는 읽기 구간은 10분까지 이어 붙입니다.
> 리포트·팀 취합에는 그날이 **샘플러 실측 / PC 하한 / 흔적 창** 중 어느 방식으로 계산됐는지 배지로 남습니다.

지금 바로 시작 (숨김 창으로 백그라운드 실행):
```
powershell -WindowStyle Hidden -ExecutionPolicy Bypass -File collect\Start-ActivitySampler.ps1
```

로그온할 때마다 자동 시작 등록 (1회만, 관리자 권한 불필요) — 등록과 동시에 지금 시작합니다:
```
powershell -ExecutionPolicy Bypass -File collect\Register-Samplers.ps1            # 창 샘플러
powershell -ExecutionPolicy Bypass -File collect\Register-Samplers.ps1 -Teams     # 팀즈 상시 샘플러도 함께
```
이 스크립트는 작업 스케줄러에 `LoadMonitor25-Sampler`(`-Teams` 면 `LoadMonitor25-TeamsSampler` 도)를 XML 로
등록합니다 — **실행 시간 제한 없음**(`schtasks /SC ONLOGON` 한 줄로 만들면 기본 3일 제한(PT72H)에 걸려
절전·잠금만 쓰는 PC 는 로그온 3일 뒤 조용히 멈췄습니다), 실패 시 1분 뒤 재시작, 배터리 제한 해제,
이미 떠 있으면 새로 띄우지 않음. 옵션: `-NoStart`(등록만, 다음 로그온부터) · `-Remove`(해제, 팀즈 것은
`-Remove -Teams`) · `-DryRun`(등록 없이 정의만 검증). 그래도 멈춘 샘플러는 대시보드가 마지막 샘플이
10분 이상 오래됐으면 자동으로 다시 띄웁니다(`autoRestartSampler`, 기본 true — 등록 작업이 있으면 그 작업을,
없으면 스크립트를 직접). 상태는 [수집 진단](`LoadMonitor25-수집진단.bat`)의 [창 샘플러] 절에서 확인합니다.

기록되는 것: 시각·프로세스명·창 제목·무입력 시간뿐. 로컬 CSV에만 저장됩니다. 무입력 시간은 PC 를
25일 이상 켜 두어도 정확합니다(예전 int32 TickCount 랩으로 '무입력 0' 이 고착되던 것 수정 — 고착된 날은
분석이 자동으로 하한 모드로 돌립니다).

## 월간 리뷰에 다른 달 일이 섞이던 문제 (LM23 에서 수정)

과거 달 리뷰에 **하지도 않은 최근 일**이 적히는 문제가 있었습니다. 원인이 네 가지였습니다.

1. **AI 채팅이 이어져 있었습니다.** 월별 리뷰는 판정이 다 끝난 뒤에 만들어지는데, 그 Copilot
   채팅에는 이미 **분석 기간 전체**(최근 달 포함)의 신호가 들어 있었습니다. 이제 달마다 새 채팅에서
   묻고, 신호에 연도를 붙이고, "목록에 없는 것은 그 달 일이 아니다"를 프롬프트에 못 박습니다.
2. **그 달의 뒷부분이 프롬프트에 없었습니다.** 표본이 90건인데 한 달 신호가 91~179건이면
   앞 90건만 나가 **월 후반이 통째로 빠졌습니다**(150건이면 17일에서 끊김). 근거를 못 받은 모델이
   빈 곳을 추측으로 메웠습니다. 이제 어느 경우에도 그 달 처음과 끝이 표본에 들어갑니다.
3. **팀즈 웹 수집이 메시지 본문의 날짜를 그 메시지 시각으로 썼습니다.** "지난 회의(6/12) 결론대로"
   같은 문장이 있으면 9월 대화가 6월 신호가 됐습니다. 이제 날짜는 화면이 알려 주는 머리 조각
   (타임스탬프·구분선)에서만 읽습니다. 창 읽기 수집기는 원래 그렇게 하고 있었습니다.
4. **메일 웹 수집이 회신 인용문의 날짜를 썼습니다.** 미리보기에 `2026년 6월 12일 … 님이 작성:`
   이 있으면 9월 회신이 6월 메일이 됐습니다. 같은 방식으로 머리 조각에서만 읽습니다.

덧붙여 AI 리뷰에 **그 달에 없는 과제 이름**이 나오면 그 항목만 버리고 콘솔에 알립니다.

3·4번은 **데이터 자체**가 잘못 들어간 것이라, 고친 뒤 그 기간을 **다시 수집·분석**해야 바로잡힙니다
(`data\m365\teams_web.csv` · `data\outlook\mail.csv` 를 지우고 [분석 실행]).

## 워크플로우는 한 번에 끝까지 판정합니다

담당자 워크플로우는 **한 번의 실행으로 모든 담당 업무를 판정**합니다. 미판정이 남으면
자동으로 마저 묻고, **한 회차에 하나도 늘지 않거나** 시간 예산을 넘길 때만 멈춥니다.
예전에는 자동 마무리가 2회차 고정이라 그래도 남으면 [이어서 분석]을 사람이 다시 눌러야 했습니다.

그래도 미판정이 남았다면 화면이 두 가지를 구분해 알려 줍니다.

- **[이어서 분석] 버튼이 보이면** — 시간 예산이나 묶음 상한에 걸려 끊긴 것입니다. 누르면 이어집니다.
- **버튼이 [워크플로우 재분석] 이면** — 더 늘릴 수 없어 멈춘 것입니다. 다시 눌러도 같습니다.
  그 단위는 신호가 얕거나(§`MIN_SIGNALS`) 판정 응답이 그 이름을 돌려주지 않는 경우입니다.

| 설정 | 기본 | 뜻 |
|---|---|---|
| `flowBudgetMin` | 120 | 전체 시간 예산(분). **0 이면 무제한**(끝까지 갑니다) |
| `flowMaxChunks` | 400 | 묶음 수 상한 — 폭주 방지용 최후 방어선 |
| `flowUnitsPerChunk` | 10 | 한 왕복에 담을 업무 수 상한(실제 제동은 답 길이 예산) |

분석 실행과 대시보드는 워크플로우에 타임아웃을 걸지 않으므로, 끊는 것은 위 예산뿐입니다.
업무가 아주 많아 오래 걸린다면 `flowBudgetMin` 을 늘리거나 0 으로 두세요.

## 상위(업무 성격) 재배치 — LM24

담당자 워크플로우에서 **과제가 엉뚱한 상위 밑에 있거나 '상위 미분류'로 빠지는** 문제를 고쳤습니다.

원인이 넷이었습니다.

1. **상위 표를 병합 전 이름으로 세고 조회는 병합 후 이름으로** 했습니다. 그래서 합쳐진 과제 중
   **흡수된 쪽의 상위 표가 통째로 버려졌습니다** — 전체 MM 의 절반을 차지한 상위가 사라지고
   0.5 MM 짜리가 과제 전체를 대표하는 일이 생겼습니다. 이제 같은 축(병합 대표)으로 셉니다.
2. **상위에 신원 축이 없었습니다.** 상위는 4개 고정 범주인데, 중위·하위와 달리 AI 가 돌려준 문자열을
   검증 없이 저장했습니다. `기술내재화`(공백 없음)가 다섯 번째 상위처럼 화면에 떴습니다.
   이제 저장할 때와 읽을 때 모두 고정 범주로 스냅합니다(못 짚으면 빈칸 — 억지로 찍지 않습니다).
3. **표가 갈려도 무조건 1위를 찍었습니다.** 51:49 와 100:0 을 똑같이 다뤘습니다. 이제 1위가 **60%**
   에 못 미치면 상위를 **찍지 않고** 그 사실을 알립니다 — 워크플로우 탭에 "상위가 갈린 과제 N건 —
   재배치 필요"로 접혀 나오고, 카드 머리말도 `상위 혼재 — 재배치 필요`로 뜹니다.
   **표가 갈렸다는 것 자체가 신호입니다**: 서로 다른 성격의 일이 한 과제로 묶였거나, 상위 판정이
   행마다 갈린 것입니다. 억지로 하나를 고르면 그 사실이 숨습니다.
4. **사람이 고칠 수단이 없었습니다.** 중위·하위는 별칭 파일로 고칠 수 있는데 상위는 없었습니다.
   이제 `config\projects.json` 의 지정 과제에 상위를 적으면 투표를 이깁니다:
   ```json
   [{"name": "광학 설계", "match": ["광학"], "level1": "신제품개발"}]
   ```

## 과제 병합을 클러스터링으로 — LM24

병합 판단을 **쌍 판정 + 그리디**에서 **가중 점수 + 제약 클러스터링**으로 바꿨습니다.

- 예전에는 근거를 **개수로 세고**(2개 이상) 그 앞에 **거부권**을 뒀습니다. 그래서 담당업무 집합이
  완전히 같은 두 과제가 "근거 부족"으로 거부되고, 이름이 닮고 제품이 같은 짝이 "담당업무 배타"로
  거부됐습니다 — **기간이 갈린 같은 과제가 바로 그 모습**이라 가장 안전한 병합이 가장 자주 막혔습니다.
- 이제 근거에 **가중치를 주어 합산**합니다. 절대 뒤집으면 안 되는 것(사용자가 `never` 에 적은 쌍,
  괄호 꼬리 상이, 숫자 토큰 상이, 둘 다 지정 과제)만 금지로 남고, 담당업무 배타·시간대 비겹침·
  진부분집합은 **감점**입니다 — 다른 근거가 충분히 세면 이깁니다.
- **거부가 우회되던 구멍을 막았습니다.** 예전에는 `never` 로 갈라 둔 두 이름이 **제3의 이름을 경유해**
  같은 무리가 됐습니다(쌍 단위 거부는 추이적으로 우회됩니다). 이제 제약을 **무리 안에서** 강제합니다.
- 무리 크기 상한도 이제 실제로 지켜집니다(예전 흡수 한도는 사슬로 우회됐습니다).
- 같은 자료면 **같은 결과**가 나옵니다 — 예전에는 MM 값만 달라져도 병합 결과가 갈렸습니다.
- 점수가 문턱 사이인 **애매한 쌍은 합치지 않고** 목록으로 보여 줍니다.

## 과제(중위) 이름 병합 — 워크플로우가 갈라지거나 겹칠 때

담당자 워크플로우에서 **같은 과제가 여러 장으로 갈라지거나 같은 업무가 두 번** 보이면
이 절을 보세요. 원인은 과제 이름의 표기 흔들림입니다 — AI 가 묶음마다 판정하다 보면
`광학 설계` / `광학설계` / `광학-설계` 처럼 띄어쓰기 하나가 달라지고, 그 순간 별개 과제가 됩니다.

LM23 은 분석 때마다 이것을 **후처리로 합칩니다**(`config\project_aliases.json`).

- **Copilot 왕복을 새로 쓰지 않습니다.** 표기 규칙과 이미 모아 둔 근거
  (정제 결과·담당 업무 집합·제품·신호 시간대)만 봅니다. 그래서 분석이 느려지지 않습니다.
- **띄어쓰기·하이픈·가운뎃점·대소문자만 다른 이름**은 그것만으로 합칩니다.
- 표기가 다르면 **서로 독립인 근거가 2개 이상**일 때만 합칩니다. 서로 다른 업무가
  한 카드에 섞이는 것이 이 기능의 유일한 심각한 실패라, 애매하면 합치지 않습니다.
- 다음은 근거가 몇 개든 **무조건 합치지 않습니다**: 괄호 꼬리가 다름(`(양산)`/`(선행)`) ·
  숫자 토큰이 다름(`2차`/`3차`) · 한쪽이 다른 쪽의 진부분집합인데 남는 낱말이 2개 이상 ·
  담당 업무가 하나도 겹치지 않음 · 신호 시간대가 아예 안 겹침 · 둘 다 지정 과제.
- 같은 단위가 두 번 판정된 흐름은 **단계가 많은 쪽만** 남깁니다. 단계를 합치지는 않습니다 —
  합치면 시간순이 깨지고 근거가 다른 신호를 가리키게 됩니다.

**담당 업무(하위) 이름도 같은 방식으로 한 겹 더 접습니다.** 예전에는 띄어쓰기·구분자만 봤는데,
실제 응답은 이렇게 흔들립니다 — 그래서 표기·구조만 보는 규칙 네 가지를 더했습니다.

| 규칙 | 예 |
|---|---|
| 꼬리 문장부호 무시 | `샘플 평가.` = `샘플 평가` |
| 앞부분이 같고 꼬리가 3자 이하 | `금형 수정` = `금형 수정 요청` |
| 어순 무시(조사 제거) | `설계 검증` = `검증 설계` |
| 낱말 하나 차이(공통 2개 이상) | `결과 분석` = `분석 결과 정리` |

여기서도 괄호 꼬리와 숫자 토큰이 다르면 무조건 합치지 않습니다 — `설계 검토 1차`/`2차`,
`검토(양산)`/`(선행)`, `설계`/`설계도`, `시험 준비`/`시험 결과 정리` 는 모두 그대로 둡니다.

무엇을 왜 합쳤는지는 **워크플로우 탭 위쪽의 접힌 줄**("이름 병합 N건 · 흐름 중복 제거 N건")에
표로 나옵니다. 콘솔에도 같은 내용이 찍힙니다.

**신호가 얕아 흐름을 만들지 않은 업무**(신호 3건 미만)는 예전에 콘솔에만 찍혀 화면에서 통째로
사라졌습니다. 이제 각 과제 머리말 옆에 "신호가 얕아 흐름을 만들지 않은 업무 N개" 로 표시되고,
마우스를 올리면 그 목록이 보입니다.

**잘못 합쳐졌으면** `config\project_aliases.json` 에서 그 줄을 지우세요. 다만 띄어쓰기만
다른 이름은 규칙이 다음 실행에 다시 합치므로, 영영 갈라 두려면 같은 파일의 `never` 에
쌍을 적습니다:
```json
{"map":   {"광학설계": "광학 설계"},
 "never": [["광학 설계", "광학설계 자동화"]]}
```
`never` 는 규칙보다 먼저 검사되므로 확실히 막힙니다. 반대로 **항상 이 표기를 쓰게** 하려면
`config\projects.json` 의 지정 과제로 등록하는 편이 낫습니다(§5-2).

> 같은 이름 축(`ukey2`)을 판정·정제 단계도 함께 씁니다. 예전에는 판정이 대소문자만 비교해서
> 새 표기가 `entities_*.json` 에 쌓이고 그것이 다음 분석의 후보로 되먹여져 **재분석해도
> 갈라진 채로 굳었습니다**. 그 고리를 끊었습니다.

## 팀즈 웹 읽기 — 팀즈가 0 건일 때 가장 먼저 (권장)

대시보드의 **[팀즈 웹 읽기]** 버튼입니다. 메일의 [Outlook 웹 읽기]와 같은 방식으로,
Copilot 이 쓰는 **전용 Edge 프로필**로 `teams.microsoft.com` 을 열어 채팅을 읽습니다
(`collect\Get-TeamsWeb.py`, 분석 실행에도 자동으로 끼어 있습니다).

- **팀즈 앱이 꺼져 있어도 됩니다.** 창 읽기(`Get-TeamsWindow.ps1`)는 화면에 실제로 그려진
  부분만 UI 자동화로 긁으므로 창 크기·테마·팀즈 버전에 따라 PC 마다 0 건이 되곤 했습니다.
  웹 경로는 화면 렌더가 아니라 문서 구조(role·data-tid·aria-label)를 읽어 그 편차가 없고,
  대화방마다 위로 되감아 **지난 날짜까지** 가져옵니다.
- **처음 한 번만** 그 Edge 창의 팀즈 탭에서 회사 계정을 선택/로그인하면 됩니다
  (Copilot·Outlook 웹과 같은 창이라, 이미 로그인했다면 그대로 동작합니다).
- LLM 을 거치지 않으므로 지어낸 행이 없고, 데이터는 PC 밖으로 나가지 않습니다.
- 결과는 `data\m365\teams_web.csv` 에 **누적**되며, Graph·창 읽기가 이미 잡은 메시지는
  대조해서 다시 적지 않습니다(경로가 겹쳐도 중복 계상 없음).

설정: `teamsWeb`(기본 true) · `teamsWebMaxChats`(기본 40 — 훑을 대화방 수, 최근 순) ·
`teamsWebBudgetSec`(기본 900 — 전체 시간 예산). 예산 안에 반드시 저장까지 끝내고, 남은
대화방은 다음 실행으로 미룹니다. 되감기는 두 번 연속 새 메시지가 없으면 그 대화에서 멈춥니다.
손으로 돌리려면:
```
python collect\Get-TeamsWeb.py --from 2026-06-01 --to 2026-06-30
```
수집 순서는 ① Graph → ② 웹 → ③ Copilot → ④ 열린 창 읽기이고, 앞이 되면 뒤는 건너뜁니다.

## 팀즈 상시 샘플러 (Copilot 이 팀즈 조회를 못 하는 계정)

회사 Copilot 이 "연결된 Microsoft Teams 데이터 조회 도구가 없어…"라고 답하면(테넌트에
Teams 커넥터가 없음) Copilot 으로 팀즈 이력을 일괄로 가져올 수는 없습니다. 위 웹 경로가
막힌 경우(웹 접속 차단 등)에는 팀즈 상시 샘플러를
켜두면 **화면에 열린 대화가 5분마다 읽혀 중복 없이 누적**됩니다 — 팀즈를 쓰는 동안
자동으로 이력이 쌓입니다 (읽기 전용·네트워크 미사용·로컬 CSV 저장).

등록은 위 §4 의 스크립트에 `-Teams` 를 붙이면 창 샘플러와 함께 됩니다(작업 이름 `LoadMonitor25-TeamsSampler`):
```
powershell -ExecutionPolicy Bypass -File collect\Register-Samplers.ps1 -Teams
```
해제: `powershell -ExecutionPolicy Bypass -File collect\Register-Samplers.ps1 -Remove -Teams`

**내가 보낸 메시지를 알아보게 하기(`teamsSelfNames`)** — 창 읽기는 보낸 사람 이름으로 내 메시지를
가립니다. `owner`·Windows 계정명·AD 표시명·'나/You' 는 자동으로 비교하지만, 팀즈 표시 이름이 그와
다르면(영문 이름, 성·이름 순서) 목록에 적으세요. 없으면 팀즈로 일한 날이 전부 '수신' 이 되어 PC 하한이
열리지 않습니다(재택 Teams 인력 로드율 절반 — 실측):
```json
"teamsSelfNames": ["홍길동", "Gildong Hong"]
```
같은 목록이 §1 의 동료 저장 파일 판정에도 쓰이며, 이름은 Copilot 프롬프트에 나가지 않습니다.
Graph·Copilot 경로도 같은 규칙으로 '팀즈(발신)' 을 판정하고, Graph 시각은 로컬 시각으로 저장됩니다
(예전엔 UTC 그대로라 낮 발신이 새벽 야근이 됐습니다).

Copilot 조회 불가는 자동으로 기록되어 다음 분석부터 헛왕복을 생략합니다. 회사가 커넥터를
켜준 뒤 재시도하려면 `data\m365\teams_copilot_unavailable.json` 을 지우세요.
창 제목 저장이 싫으면 `"storeWindowTitle": false`.

**설정 안 해도 됩니다.** 비워두면 분석 시 팀즈는 **Copilot 무개입 추출**로 자동
대체됩니다(관리자 불필요, 이미 동작 확인됨). Graph 직접 수집은 원문이 더 정확할 뿐입니다.

"graph": { "clientId": "xxxxxxxx-xxxx-....", "tenantId": "organizations", ... }

python collect\Get-TeamsChats.py --login-only

상태 확인: `python collect\Get-TeamsChats.py --status`

## 5-1. 팀 취합 업로드 — 자동 전송 없음

팀 서버는 특정 망에서만 닿습니다. 그래서 **분석은 묶음을 준비만** 하고, 전송은 사용자가 그 망에서
버튼으로 합니다.

1. `config.json` 의 `teamServerUrl` 에 팀 서버 주소를 적습니다(대시보드 카드에서 바로 고쳐도 됩니다).
2. 분석을 실행하면 `report\upload_pending\` 에 기간별 묶음이 쌓입니다 — 이때는 아무것도 전송하지 않습니다.
3. 서버에 닿는 망(사내망)에서 대시보드 **[팀 취합 업로드]** 카드의 [연결 확인] → [팀 서버 업로드].
   밀린 기간이 여러 개면 한 번에 올라갑니다. 대시보드를 열기 싫으면 `LoadMonitor25-팀업로드.bat` 더블클릭.
4. 서버 대신 공유폴더를 쓰려면 [공유폴더로 저장] (경로를 물어봅니다 — `teamShareDir` 기본값).

닿지 않는 망에서 눌러도 묶음은 그대로 대기하므로 손실이 없습니다. 예전처럼 분석 직후 자동 전송까지
시도하려면 `teamUpload.auto` 를 `true` 로 두세요(실패해도 대기로 남습니다).

보내는 것은 그 기간의 판정 결과와 근거 신호 목록입니다 — **메일 제목·회의 제목·동료 이름이 포함될 수**
**있습니다**(개인 폴더 신호는 `excludePathKeywords` 로 이미 제외됨). 사내망 전용으로만 쓰세요.

## 5-2. 팀 취합 — 결과를 어디에 넣나

취합은 **인원별 폴더 하나 = 한 사람**으로 읽습니다. 폴더 안에 그 기간 결과 파일들과
`member.json`(요약)이 함께 있어야 그 사람이 취합에 잡힙니다. `member.json` 이 없으면 그 폴더는
무시되므로, 파일만 복사해 넣으면 취합에 나타나지 않습니다.

```
<취합 위치>\
  홍길동\
    member.json                       ← 이게 있어야 인원으로 인식
    mm_rows_20260601-20260630.csv
    mm_rows_20260601-20260630_refined.csv
    signals_20260601-20260630.csv
    mm_meta_20260601-20260630.json
    pivots_20260601-20260630.json
    entities_20260601-20260630.json
    ai_narratives_20260601-20260630.json
    agentic_20260601-20260630.json
    workflow_20260601-20260630.json
  김철수\
    ...
```

### 방법 A — 팀 서버 (권장)

1. 팀 공용 PC 에서 서버를 켭니다 — **대시보드의 [팀 서버 (이 PC 에서 켜기)] 카드에서 [팀 서버 시작]**
   (또는 `LoadMonitor25-팀서버.bat`). 카드가 **이 PC 의 주소**(`http://<IP>:9310`)를 알려 주니 그 값을
   팀원에게 그대로 전하면 됩니다. 처음 켤 때 방화벽 허용 창이 뜨면 허용해야 다른 PC 에서 접속됩니다.
   그 PC 의 `teamdata\` 가 위 그림의 <취합 위치>가 됩니다(자동 생성).
2. 각자 대시보드 **[팀 취합 업로드]** 카드에서 주소를 확인하고 [팀 서버 업로드].
   전송이 끝나면 **어느 폴더에 담겼는지**(`저장 위치: ...`)가 함께 찍힙니다 — 이 PC 에 LoadMonitor
   폴더가 여럿이면 꼭 확인하세요.

## 5-3. PC 를 2~3대 쓸 때 — 폴더 통째로 옮기기

분석이 끝난 폴더는 대개 **우리 자신이 잡고 있어** 그냥 옮기면 "사용 중" 오류가 납니다
(대시보드·팀 서버·Copilot 전용 Edge·상시 샘플러, 그리고 그 폴더를 열어 둔 탐색기 창).

**`LoadMonitor25-이동준비.bat`** 을 실행하거나 대시보드의 **[PC 이동 준비]** 버튼을 누르세요:

1. 우리 프로그램을 모두 종료합니다 (일반 Edge 는 건드리지 않습니다 — Copilot 전용 프로필만)
2. 탐색기가 그 폴더를 열고 있으면 **어느 창인지** 알려 줍니다
3. 폴더 이름을 잠깐 바꿔 **정말 옮길 수 있는지 실제로 확인**합니다 (원래 이름으로 되돌립니다)
4. 안 되면 사유와 함께 흔한 원인·조치를 안내합니다

확인이 끝나면 `report\move_ready.txt` 가 남습니다. 수집 데이터와 분석 결과는 지우지 않습니다.

정상적으로 끝나면 **정리 창은 키를 누르지 않아도 몇 초 뒤 스스로 닫힙니다**(대시보드·팀 서버·샘플러도
함께 닫힙니다). 화면을 더 보고 싶으면 그 사이에 아무 키나 누르면 자동 닫힘이 멈춥니다.
**실패했을 때는 사유를 읽어야 하므로 닫히지 않고 기다립니다.**

### 옮기는 것이 느릴 때

폴더 용량의 대부분은 `data\copilot_profile`(Copilot 로그인용 Edge 캐시)입니다. 실측으로 전체
2,679개 551.6 MB 중 2,507개 529.2 MB 가 그것이었습니다. **이 폴더는 빼고 옮기세요.**

그 안의 로그인 정보는 Windows DPAPI 로 **지금 이 PC·이 계정에 묶여** 있고 그 열쇠는 LoadMonitor 폴더
바깥(`%APPDATA%\Microsoft\Protect\`)에 있습니다. 그래서 폴더를 통째로 옮겨도 로그인은 살아나지
않습니다 — 어차피 새 PC 에서 한 번 로그인해야 합니다. 빼면 파일이 2,679 → 148개로 줄어 복사가
훨씬 빨라집니다(로컬 SSD 실측 3.0초 → 0.2초).

이동 준비 창이 끝나면 **그 PC 의 실제 숫자**와 함께 붙여 넣을 명령 한 줄을 보여 주고 클립보드에도
복사해 둡니다. 대상 경로만 바꾸면 됩니다.

```
robocopy "D:\LoadMonitor25" "E:\LoadMonitor25" /E /XD copilot_profile __pycache__ .ruff_cache /R:1 /W:1 /MT:16
```

- `/MIR` 은 쓰지 마세요 — 대상 폴더에 있던 다른 내용을 지웁니다.
- 원본의 `copilot_profile` 은 **지우지 마세요.** 지금 이 PC 에서는 그 로그인이 살아 있습니다.
  새 PC 가 잘 도는 것을 확인한 뒤에 정리하시면 됩니다.
- 새 PC 에서는 `LoadMonitor25-UI.bat` → **[AI 연결 진단]** → 열린 전용 Edge 창에서 회사 계정 로그인
  1회 → **[AI 연결 진단]** 을 다시 눌러 성공을 확인한 뒤 분석을 실행하세요.
  (폴더가 없으면 도구가 알아서 새로 만듭니다.)
- 사내망에서 python.org 에 닿지 않는다면 `python\` 폴더는 **반드시 함께 가져가세요**
  (`tools\Get-EmbeddedPython.ps1` 은 인터넷이 필요합니다).

옮긴 PC 에서 `LoadMonitor25-UI.bat` 을 실행하면:

- 지난 PC 의 수집 데이터는 `data\추가PC\<이름>\` 으로 자동 보관되고
- 분석은 **두 PC 를 합쳐** 계산합니다
- `report\upload_pending\` 의 업로드 대기 묶음도 함께 따라갑니다

> 폴더 안에서 정리 스크립트를 직접 실행하지 마세요 — 그 스크립트 자신이 폴더를 잡아 확인이 실패합니다.
> bat 과 버튼은 `%TEMP%` 로 복사해 실행하므로 그런 일이 없습니다.

### 근태·회의 판정 규칙 (2차 감사 반영 — 설정 없이 자동)

- **동료 연차 공유 초대는 부재로 세지 않음** — `[연차] 홍길동` 식 팀 공유 초대(받은 초대인데 내 상태가
  부재중이 아님)·취소된 초대·거절·미응답 초대는 내 근태가 아닙니다. 내 근태는 **내가 부재중(OOF)으로
  표시한 일정**만. COM 이 아닌 폴백 경로(색인·웹·Copilot)는 '한가함' 일정만 거릅니다.
- **복합 근태 제목 인식** — `여름휴가` `연차휴가` `오후반차` `경조사` `대체휴무` 처럼 근태어가 다른 말과 붙은
  제목도 부재로 봅니다(`휴가철 안전 캠페인`·`휴무일 근무 협조`·'연차 사용 현황' 같은 안내·공지는 제외 — 놓치면
  정상 근무로 남으므로 애매하면 안 잡는 쪽). 종일이 아닌 부재중 일정은 길이와 제목(반차·오전·오후)으로
  0.5일 / 1.0일을 판정합니다.
- **종일 출장·현장·교육·워크숍은 근무** — 종일 일정이 부재중/바쁨이거나 제목에 `출장 현장 외근 교육 세미나
  전시 박람회 고객사 방문 시험 workshop trip site training offsite field` 가 있으면 그날을 **표준일 8h**
  (반차면 4h) 하한으로 인정하고 부재 추정에서 뺍니다(`mm.offsiteAsWork`·`offsiteKeywords`). 예전엔 0h,
  PC 까지 꺼져 있으면 '부재 추정' 이었습니다(현장 주 2일 −36pt). 다일 시간제 일정은 날짜별로 잘라 각 날 8h 상한.
- **회의가 아닌 약속은 회의 시간이 아님** — 참석자 없는 개인 약속(재택근무 블록·'치과')은 회의 구간·PC 하한
  게이트에 들어가지 않습니다(출장 제목이면 위 규칙으로만 인정). 회의 제목에도 §2 의 `excludePathKeywords`
  가 걸립니다('병원 진료(개인)' 8h 방지).
- **미응답 초대** — `tentativeMeetings: "count"`(기본) 에서는 미정·미응답도 계상해 COM PC 와 폴백 PC 의
  값이 같습니다. 초대에 응답하지 않는 습관이면 그대로 두세요(§9 표).
- **폴백 경로의 한계와 보완** — Windows Search 색인은 반복 회의를 전개하지 못하므로(마스터 1건)
  `mail_source.json` 에 `calendar_complete:false` 를 남기고 웹 경로(주 보기)로 일정만 다시 시도합니다.
  웹 경로는 '6월 1일 ~ 6월 5일' 식 다일 일정을 시작~끝으로 읽고(예전엔 첫날 하루), 발신함 판정은
  폴더 이름 완전 일치라 'presentation'·'Sent from my iPhone' 수신 메일이 발신으로 둔갑하지 않습니다.
- **공휴일** — 설·추석·대체공휴일·선거일은 연도별 표(`core\extract.py` KR_HOLIDAYS, 2025~2027)가 내장돼
  `holidays` 를 비워 둬도 됩니다. 내장 표에 없는 연도·임시 공휴일만 적고, 해가 바뀌면 정부 공고로 표를
  갱신하세요. 추정 부재·공휴일은 투입 MM 의 분모(평일수)에서도 빠집니다.

### 팀즈 시각 형식이 특수한 PC (`teamsTimeRegex`)
팀즈 창 읽기는 이 PC 의 Windows 지역 설정(오전/오후 표기·시각 구분자·날짜 순서·월 이름)에서 형식을 자동
구성하고, 한 줄도 못 잡으면 일반 형식(`숫자:숫자` / `숫자.숫자`)으로 다시 시도합니다. 그래도 0건이면
[수집 진단]의 "불일치 예"(마스킹된 줄)를 보고 `config.json` 의 `teamsTimeRegex` 에 .NET 정규식을 적으세요.
그룹 순서는 `1=앞 오전/오후 표기, 2=시, 3=분, 4=뒤 표기` 이며 빈 그룹도 됩니다. 예) `14h10` 표기:
`()?\b(\d{1,2})h(\d{2})\b()?`

## 7. noticeSenders — 공지·알림 메일 제외

정부24·인화원·윤리사무국·innoHR 같은 정보성 발신은 업무도, 연결성도 아닙니다.
발신자 이름에 이 키워드가 있으면 **완전 제외**됩니다(신호 출처 카드의 '제외'에 집계):

```json
"noticeSenders": ["정부24", "인화원", "윤리사무국", "innoHR", "no-reply", "뉴스레터", "회사알림계정추가"]
```

명단에 없어도 **5통 이상 받았는데 내가 한 번도 회신한 적 없는 발신자**는
자동으로 알림성으로 판정해 0.2배로 감쇠합니다(출처에 '메일(수신전용)'으로 표시).
리뷰에서 이상한 발신자가 보이면 그 이름을 명단에 추가하면 즉시 사라집니다.

매칭은 발신자 표시 이름을 `/`·`|`·괄호·공백으로 **조각낸 뒤** 비교합니다 — `시스템` `공지` `알림` `설문`
`보안` `광고` `마케팅` `viva` 같은 일반 명사는 조각 전체가 같을 때만, 나머지(`no-reply`·`정부24`)는 조각
시작 일치. 그래서 `홍길동/책임/LiDAR시스템팀` 이나 `공지영` 은 공지가 아니고, **내가 회신한 적 있는
발신자는 무조건 공지가 아닙니다**. 기본 목록에서 `system` 은 뺐습니다(파트명 System/OE/ME/EE 와 충돌).
`nonWorkKeywords` 도 `취소:`·`Canceled:` 류는 접두 일치, 근태어는 위 §6 토큰 규칙, `미리 알림` 은
정확 일치라 '연차 사용 현황 안내' 회의나 파일 이름이 지워지지 않습니다.

## 8-1. copilotAuto — Copilot 무개입 왕복 (기본값 그대로 두면 됩니다)

| 키 | 기본 | 뜻 |
|---|---|---|
| `url` / `port` | m365 chat / 9333 | Copilot 주소 · 전용 Edge 의 디버그 포트 |
| `stablePolls` × `pollSec` | 5 × 3초 | 응답이 이 시간 동안 안 변하면 완료로 판정 |
| `replyTimeoutSec` | 240 | 한 왕복의 대기 한도(초). 긴 프롬프트를 조각으로 나눠 보내면 조각 수만큼 곱해 기다린다 |
| `model` | "GPT-5.6" | 메뉴에서 고를 모델 — 하이픈·공백·점 차이는 무시하고 찾는다 |
| `judgeChunk` | 40 | 판정 한 왕복에 넣는 신호 수. 응답이 잘리거나 실패하면 줄인다(`python judge.py --chunk N` 이 우선) |
| `refineChunk` | 20 | 정제 한 왕복에 넣는 행 수. 40행은 근거 포함 12,000자로 입력 한도를 넘겼다(실측) |
| `sendSenderAddress` | false | 메일 상대의 **주소**를 프롬프트에 넣을지. 기본은 도메인(`@회사.com`)만 — 판정에는 그걸로 충분하고 개인 식별 정보가 덜 나간다. 어느 쪽이든 **사람 이름·MM 은 보내지 않는다** |

프롬프트가 Copilot 입력 한도(9,000자)를 넘으면 **줄 경계 8,000자 조각으로 나눠 보내고** 답 끝의
`[[전송끝]]` 서약으로 완료를 판정합니다(`tools\copilot_auto.py`). 따로 설정할 것은 없고, 조각 수만큼
왕복이 길어질 뿐입니다(`replyTimeoutSec` 도 조각 수만큼 곱해 기다립니다).

## 8-2. 캐시 파일 — Copilot 이 채운 것, 한 줄 지우면 그 항목만 원복

Copilot 이 한 번 정한 병합·분류 결과는 파일에 누적돼 다음부터는 묻지 않습니다. 결과가 이상하면
그 파일에서 **해당 줄만 지우고** 다시 돌리면 그 항목만 다시 묻고, 파일을 통째로 지우면 전부 다시
묻습니다. 원본 결과(mm_rows·signals)는 건드리지 않으므로 지워도 잃는 것은 없습니다.

| 파일 | 어디에 | 무엇 |
|---|---|---|
| `config\detail_aliases.json` | 개인 폴더 | 세부업무 표기 병합 맵(규칙 + Copilot). 옛 `report\보완툴\detail_aliases.json` 은 첫 실행에 자동 흡수 |
| `team_aliases.json` | 팀 공유폴더(서버 PC 면 `teamdata\`) 루트 | [Copilot으로 유사 항목 정리] 결과 — 과제·세부업무의 갈라진 표기 → 대표 이름. [정리 되돌리기] 가 지우는 파일 |
| `team_series.json` | 〃 | 과제 시리즈(같은 계열 과제) 묶음 |
| `team_pjclass.json` | 〃 | 과제 분류 — 애매한 이름만 Copilot 에 1회 |
| `team_detail_groups.json` | 〃 | 세부업무 계열 통합(의미 병합) |
| `team_cand_groups.json` | 〃 | 후보 이름 병합 |
| `team_agentic_adjust.json` | 〃 | (캐시 아님) 팀 통합 보고서의 [조정 내용 내보내기] 가 만든 제외 목록(`excluded_people`·`excluded_cells`). 손으로 고치는 파일 — 형식이 깨지면 무시하고 경고만 |

팀 파일은 팀 취합 화면의 [정리 되돌리기] 에서 "다른 캐시도 함께 지울까요?" 로 한 번에 지울 수 있습니다.
Copilot 에 보내는 것은 어느 파일이든 **과제·업무 이름 목록뿐**입니다(사람 이름·MM 없음).

## 8-3. 수동 기록 — PC 밖 업무 한 줄 (출장·조립·현장·장비 점검)

키보드 밖에서 한 일은 어떤 수집기도 못 봅니다. 그런 날은 **Outlook 에 종일 일정(부재중 표시, 제목에
출장·현장 등)** 을 남기는 것이 가장 쉽고(§6 규칙으로 8h 인정), 일정을 남기지 못했거나 시간이 다르면
하루 한 줄만 기록하세요:

```
powershell -ExecutionPolicy Bypass -File collect\Add-WorkLog.ps1 -Category 출장 -Hours 8 -Note "고객사 방문"
powershell -ExecutionPolicy Bypass -File collect\Add-WorkLog.ps1 -Category 장비점검 -Hours 2.5 -Date 2026-08-10 -Entity "LiDAR 시험기"
```

- `data\manual\worklog.csv`(`date,category,hours,entity,note,user`)에 추가됩니다. 메모장으로 같은 형식의 줄을
  직접 적어도 됩니다(날짜는 `YYYY-MM-DD`, 시간은 0 초과 24 이하).
- 분석은 그날 투입을 **기록 시간 이상**으로 봅니다(대체가 아니라 하한 — PC 흔적이 더 길면 그쪽). 그날은 능동
  흔적이 있는 날로 취급돼 부재 추정에서 빠지고, '수동기록' 신호(가중치 = 시간 × 2)가 과제 배분에도 들어갑니다.
- 근거 카드·리포트에 '수동 기록 N일 Mh' 로 표시되고, 추가 PC 폴더(`data\추가PC\<이름>\manual\`)의 기록도 합쳐집니다.
- 예전(LM22 1차까지)에는 이 파일을 아무 코드도 읽지 않아 기록해도 0h 였습니다.

## 9. MM 산정 (v8 — 투입 ÷ 가용 = 로드율)

```
1 MM      = 8h × 그 달 평일수
가용 MM   = (평일수 − 부재일수) ÷ 평일수     ← 연차·휴가는 일자에서 뺀다
투입 MM   = 실제 투입시간 ÷ (8h × 평일수)    ← 상한 없음(하루 24h 물리 한계만)
로드율(%) = 투입 ÷ 가용 × 100
```

| 상황 | 처리 |
|---|---|
| 평일 | 흔적(회의·샘플러·신호 세션) 구간의 합집합. 능동 흔적(산출물·발신·수락 회의·샘플러)이 있으면 **PC 가동 구간**(`data\pc\pc_spans.csv` ∩ 주간 창 08~19, ≤11h)을 구간째 합친다 — 점심 1h(흔적 없는 만큼) 차감, PC 가 꺼진 시간의 수락 회의는 따로 더해진다. 절전·잠금으로 꺼진 공백 중 점심·회의로 설명되는 만큼은 근무 |
| 항상 켜 두는 PC | 절전·종료 이벤트가 없어 24h 가동으로 보이는 PC 는 '첫 능동 흔적 −30분 ~ 마지막 능동 흔적 +30분' 까지만 하한(수집기가 `[pc-on] 절전·종료 이벤트 없음` 경고 — 창 샘플러 권장). 잠금 이벤트(4800/4801)는 관리자 권한이 없으면 못 읽어 `data\pc\pc_source.json` 에 `lock_events: unauthorized` 로 남는다 |
| PC 기록 없는 평일 | System 로그 롤오버·힌트 없음 → 능동 흔적·회의의 첫 −30분 ~ 마지막 +30분 을 하한으로(`pcFloorFallback: "trace"`), 근거 카드에 'PC 기록 결측 평일 N일' 로 계수. 그 달 PC 기록이 40% 미만이면 '하한 미적용' 배지 |
| 창 샘플러 가동일 | 덮은 시간은 키보드·마우스 실측(같은 창 읽기 10분 이어붙임, ≤60분 공백 잇기 `samplerGapBridgeMin`), 덮지 않은 가동 구간(켜기 전·죽은 뒤·중간 공백)은 하한. 하루 ≥14h 를 덮는데 무입력이 전혀 없는 고착일은 하한 모드로 폴백 |
| 연차·휴가 종일 | 흔적이 없으면 0h, 있으면 흔적만큼 그대로(자르지 않고 이상치로 표시) · **가용에서 그 날짜를 뺌** → 로드율 100% 유지. 동료 연차 공유 초대·취소 초대는 내 부재가 아님(§6) |
| 반차·시간제 부재 | 부재 0.5일 — PC 하한을 표준일 × 0.5(=4h)로 제한하되 실측 흔적이 더 길면 인정 (가용도 0.5일 차감) |
| 종일 출장·현장·교육 | 부재중/바쁨 종일 일정 또는 `offsiteKeywords` 제목 → 표준일 8h × (1−부재) 하한, 능동 취급, 부재 추정 제외(`offsiteAsWork`). 다일 시간제 일정은 날짜별 8h 상한 |

### 측정 방식 배지·커버리지 — 팀 비교 전에 볼 것

같은 근무라도 **PC 전원 정책·권한·샘플러 유무**에 따라 수집 환경이 달라 로드율이 66~127% 로 갈렸습니다(2차 감사
실측). 그래서 분석 결과(`mm_meta_*.json` 의 `measure`·`coverage`·`cfg_used`)와 팀 취합 페이로드에 다음이 실립니다:

| 항목 | 뜻 |
|---|---|
| `measure.method` · `sampler_days` / `pc_floor_days` / `pc_record_days` / `trace_window_days` / `offsite_days` / `manual_days` | 그 기간 각 날이 어느 방식(샘플러 실측 · PC 하한 · 흔적 창 폴백 · 종일 행사 · 수동 기록)으로 계산됐는지 일수 |
| `floor_blocked_passive_days` | 수동 흔적만 있어 하한이 닫힌 평일 수 — 크면 `teamsSelfNames`·`watchFolders` 부터 확인 |
| `pc_coverage_by_month` | 월별 PC 기록 생존 비율 — 0.4 미만인 달은 '하한 미적용' 배지 |
| `coverage.grade` | `reliable`(신뢰: PC 기록 40% 이상·샘플러·캘린더 모두 있음) / `caution`(주의: 일부 결측) / `unreliable`(측정 불충분: 전부 결측) — 이유는 `reasons`. 팀 취합에서 측정 불충분은 팀 평균·순위·과제 매트릭스에서 빼고 별도 행으로 |
| `cfg_used` | standardDayHours·usePcFloor·pcFloorNeeds·dayWindow·lunch·dinner·tentativeMeetings·holidays 수·offsiteAsWork·samplerGapBridgeMin — 팀 다수와 다르면 인별 표에 **'산식 설정 상이'** 배지 |

로드율의 분모는 `standardDayHours × 평일수` 라 **standardDayHours·holidays·lunch·dayWindow 는 팀 전원이 같은 값**이어야 합니다.
팀에서 정한 `config.default.json` 값을 그대로 쓰고 개인이 바꾸지 마세요(다르면 '산식 설정 상이' 배지가 붙습니다). 팀 통합 보고서의
인별 표에서 측정 방식 배지가 다른 사람끼리(예: 샘플러 vs 하한) 소수점 차이를 따지지 마세요 — 모드 간 계통 차는 ±5pt 안으로
맞췄지만 0 은 아닙니다.

**로드율이 낮게 나오면** 먼저 UI의 'MM 산정 근거' 카드에서 *흔적 없는 평일*·*연속공백 제외 횟수*·*PC 기록 결측
평일*·*수동 흔적만 있는 평일(하한 닫힘)* 을 보세요. 이 수가 크면 실제로 덜 일한 게 아니라 수집이 덜 된 것입니다
(클래식 Outlook을 켠 상태로 재실행, `watchFolders` 확인, 팀즈 창 읽기면 `teamsSelfNames`, git 사용자는 `[git] 실행 파일 없음`
여부, 항상 켜 두는 데스크톱은 창 샘플러 등록). 출장·현장이 0h 면 §6 의 종일 일정 규칙과 §8-3 수동 기록을 쓰세요.
