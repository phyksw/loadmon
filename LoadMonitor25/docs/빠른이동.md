# 여러 PC 수집과 빠른 이동

로컬 PC A → 로컬 PC B → 최종 클라우드 PC 순서로 사용하는 경우, 앞의 PC에서는 수집만 하고 마지막 PC에서 모은 자료를 분석합니다. 각 PC에서 전체 AI 분석을 반복하는 시간을 줄일 수 있습니다. 최종 PC는 이 Windows 프로그램과 회사 Copilot을 사용할 수 있어야 합니다.

## 권장 사용 순서

1. 첫 로컬 PC에서 기간을 선택하고 **추가 PC 수집**을 누릅니다. 첫 PC에서도 수집만 하는 버튼으로 사용할 수 있습니다. 이 단계의 Outlook·Teams 대체 수집에서 회사 로그인이 필요할 수 있습니다.
2. 수집이 끝나면 **PC 이동 준비**를 누릅니다. 또는 **LoadMonitor25-이동준비.bat**을 실행합니다. 전용 창에서 프로그램 정리 → 폴더 확인·원복 → 이동 ZIP 생성·검증을 이어서 처리합니다. 기존 **LoadMonitor25-빠른이동.bat**도 같은 이동 준비로 연결됩니다.
3. 전용 창의 **완료** 표시와 ZIP 경로를 확인한 뒤 ZIP 하나만 다음 PC에 복사합니다. 창이 열렸다는 안내는 완료가 아닙니다. ZIP은 프로그램 폴더의 바로 바깥에 `LoadMonitor25_이동_날짜_고유값.zip`으로 생깁니다.
4. 다음 PC의 **새 빈 폴더**에 압축을 풉니다. ZIP 안에는 프로그램 폴더 하나가 있으므로 그 안의 `LoadMonitor25-UI.bat`을 실행합니다. 기존 자료가 있는 다른 설치본에 덮어 풀지 않습니다.
5. 두 번째 로컬 PC에서는 그 PC의 작업 폴더·로그인을 확인하고 **추가 PC 수집**을 실행한 뒤 같은 방식으로 이동 ZIP을 만듭니다. 한 작업 사본을 순서대로 옮기면 이전 PC 자료의 보관 구조가 유지됩니다.
6. 마지막 PC에서는 같은 분석 기간을 선택하고 **모은 자료 분석**을 누릅니다. 이 버튼은 그 PC의 자료를 새로 수집하지 않고 이미 모인 자료로 AI 분석을 실행합니다. 마지막 PC의 업무도 수집하려면 먼저 추가 PC 수집을 실행합니다.

보고서 파일만 다시 만들 때는 **보고서 만들기**를 사용합니다. 이미 필요한 자료를 모았는데 전체 분석을 실행하면 수집·AI 판정을 반복할 수 있습니다.

## 무엇을 옮기는가

| 포함 | 복사에서 제외 |
|---|---|
| `config/` 전체: 개인 설정, 과제, 제외·별칭·보정 | 전용 `data/copilot_profile/`, `data/추가PC/<PC>/copilot_profile/` 및 정확히 지정된 별도 브라우저 프로필 |
| `data/` 전체: PC 식별 기록, 원시 자료, 수동 기록, `추가PC/` | 루트·코드 폴더의 `__pycache__/`, `.ruff_cache/`, `.pytest_cache/` |
| `report/` 전체: AI 결과, 보고서, 업로드 대기·이력 | 루트·코드 폴더의 `.git/` |
| `teamdata/`, 프로그램 소스·내장 Python | 이전 이동 도구가 만든 manifest는 새 manifest로 갱신 |

원본 폴더나 캐시는 삭제하지 않습니다. 일반 이름에 `cache`나 `log`가 들어간 파일도 일괄 삭제하거나 제외하지 않습니다. 판정 결과와 사용자 교정은 다시 만들기 어려운 상태이므로 보존합니다.

위 개발 캐시 제외는 프로그램 루트 및 `core/`, `ui/`, `tools/`, `collect/`, `python/` 내부에만 적용합니다. 자료·설정·보고서·사용자 폴더 안의 같은 이름은 보존합니다.

전용 브라우저 프로필은 크고 작은 파일이 많으며, 다른 PC에서 로그인 정보를 그대로 사용할 수 없는 경우가 있습니다. 이동 ZIP에서는 제외하고 새 PC에서 회사 계정에 로그인합니다. 사용자 지정 `copilotAuto.profileDir`이 상대경로이면 정확한 폴더를 확인할 수 없어 이동을 중단하므로 절대경로로 확인합니다. PC별 작업 경로·예약 작업 등록도 새 PC에서 확인해야 합니다.

이 ZIP에는 실제 업무 자료와 개인 설정, 보관된 인증 상태가 들어갈 수 있습니다. 자신의 PC 사이에서 자료를 옮기는 용도로 사용합니다. 다른 사람에게 프로그램만 배포할 때 쓰는 `Make-Package.ps1`은 개인 설정을 기본값으로 교체하고 data/report를 비우므로 자료 이동용으로 사용하지 않습니다.

## 중지·변경·잠금 처리

- 압축 전에 파일 목록을 고정하고, 복사 중과 완료 전에 목록·크기·수정 시각·파일 정체성을 확인합니다. ZIP 내부 파일도 SHA-256으로 대조합니다.
- 수집·분석·샘플러 때문에 원본이 바뀌거나 파일을 읽지 못하면 완료 ZIP을 게시하지 않습니다. 해당 작업을 마친 후 다시 실행합니다.
- PC 이동 준비 중에는 새 분석·변경 작업과 샘플러 자동 시작을 막습니다. 대시보드는 종료되고, 전용 이동 준비 창에서 ZIP 생성 결과를 확인합니다. 그 사이 원본 자료를 수정하지 않습니다.
- 링크/junction, 원본 폴더 안 출력, 기존 ZIP 덮어쓰기를 허용하지 않습니다.
- 압축한 뒤 SHA-256·포함 파일 목록이 담긴 `_LM25_TRANSFER_MANIFEST.json`을 함께 남깁니다. 그 ZIP을 푼 사본에서도 다시 이동 ZIP을 만들 수 있습니다.

**PC 이동 준비**는 해당 설치의 프로그램을 정리하고 폴더 이름을 잠시 바꿨다가 원복한 후 ZIP을 만듭니다. 다른 이름의 설치와 다른 브라우저 프로필은 종료 대상에서 제외합니다. 폴더 원복이나 ZIP 생성에 실패하면 **미완료**와 원본 위치를 표시합니다. 용량 표시를 위해 폴더 전체를 반복 탐색하던 작업은 제거했습니다.

이전 PC 자료 보관에 실패하면 새 PC의 수집을 중단해 기존 자료를 덮지 않습니다. 로그에 표시된 잠금을 해소한 뒤 다시 실행합니다. PC 가동 기록은 `data/pc/pc_on.csv`와 이전 형태인 `data/pc_on.csv`, 추가 PC의 같은 배치를 모두 읽습니다. 상위 폴더를 임의로 더 씌워 넣지 않습니다.

월간 리뷰는 **리뷰 분석 기간**에서 보존된 기간을 선택할 수 있습니다. 코멘트 일부 달의 재생성이 실패하면 그 달의 기존 코멘트를 보존하고 표시합니다. 이동 ZIP에는 월간 코멘트와 기존 보고서가 포함됩니다.

## 같은 자료의 재분석 줄이기

**모은 자료 분석**은 완료된 과거 기간에 대해 입력·설정·코드·출력과 정상 완료 증거가 모두 같을 때만 결과를 재사용합니다. 기존 버전의 파일이 있다는 이유만으로 완료 결과로 인정하지 않습니다. 처음 실행하거나 자료가 달라지면 전체 분석합니다.

재사용 기록은 같은 PC의 같은 프로그램 경로에서 24시간 동안 유효합니다. PC나 경로를 옮긴 첫 실행, 팀 공유 또는 자동 업로드가 설정된 실행은 전체 분석합니다. 과제 체계·별칭·파일 힌트가 분석 중 새로 만들어지거나 바뀌면 그 실행은 재사용 대상으로 등록하지 않습니다.

오늘을 포함한 기간은 현재 시각이 가용 MM에 영향을 주므로 다시 분석합니다. 부분/실패/테스트 응답, 손상·삭제된 결과, 변경된 사용자 지정이나 별칭, 검사할 수 없는 외부 근거가 있으면 재사용하지 않습니다. **강제 재분석**을 체크하면 캐시가 있어도 다시 실행합니다. 재사용을 보류한 사유는 실행 로그에 표시합니다.

화면에는 최근 실행에서 오래 걸린 단계와 소요시간을 표시합니다. 첫 AI 분석 자체는 자료량·기간·회사 Copilot의 응답 및 재시도에 따라 오래 걸릴 수 있습니다. 실제 1시간을 특정 시간으로 줄인다는 보장은 이번 변경에서 하지 않습니다.

## 명령으로 실행

프로그램 폴더에서 내장 Python을 사용할 수 있습니다. 아래 `transfer.py` 직접 명령은 프로그램 정리를 수행하지 않는 별도 진단·고급 사용용입니다. 일반 이동은 위 **PC 이동 준비**를 사용합니다. BAT에 쓰던 `--plan/--json/--root/--output` 인자는 아래 Python 명령으로 사용합니다.

```powershell
# 파일을 만들지 않고 포함 계획 확인
.\python\python.exe -B .\tools\transfer.py --plan

# 원본 바깥에 이동 ZIP 생성
.\python\python.exe -B .\tools\transfer.py

# 날짜는 필요한 기간으로 변경: 각 로컬 PC에서 수집만
.\python\python.exe -B .\run.py --from 2026-08-01 --to 2026-08-31 --collect-only

# 최종 PC에서 모은 자료 분석, 검증된 완료 결과가 있으면 재사용
.\python\python.exe -B .\run.py --from 2026-08-01 --to 2026-08-31 --skip-collect --ai --reuse-complete
```

이동 폴더를 여러 개 중첩해서 합치거나 `/MIR`로 서로 달라진 두 PC의 자료를 덮어쓰지 않습니다. 한 작업 사본을 순서대로 전달하는 방식입니다. 독립적으로 수정된 사본을 자동 병합하는 증분 동기화 기능은 포함하지 않습니다.
