메일·Teams에서
“업무를 설명할 근거”를 모읍니다.

7건이라는 숫자보다 중요한 것은 요청·응답·결정의 내용과 연결입니다. 수집부터 업무 분석까지, 확보한 내용과 모르는 범위를 함께 전달하도록 바꿨습니다.

구현 설명 · 실제 회사 계정 실행 결과 아님

1. LM에 왜 이 자료가 필요한가요?

누가

나에게 맡긴 업무

파일 이름만으로는 요청한 사람, 담당자, 업무 배경을 알기 어렵습니다.

무엇을

요청과 산출물

메일·채팅의 지시와 응답을 문서·커밋·수동 기록과 연결합니다.

어떻게

진행 과정과 자동화 후보

검토·수정·승인 흐름을 해석하고 반복 작업의 자동화 가능성을 살핍니다.

서로 다른 두 축: 메일·채팅은 업무의 내용과 관계를 설명합니다. 시간·MM은 기존 활동 시각·회의·PC 기록 등의 산식으로 추정합니다. 메시지 수가 늘었다고 그만큼 근무시간이나 절감량이 늘었다고 말할 수 없습니다.

2. 왜 Teams 7건·메일 0건이 나올 수 있나요?

현재 보고된 숫자의 직접 원인은 다른 PC의 실행 결과가 없어 확정하지 못했습니다. 코드에서 확인한 구조는 아래와 같습니다.

수집의 문제

기존 Teams는 열린 창·채팅목록에 의존했습니다. Outlook 웹의 기간 검색 구문도 공식 안내와 달랐습니다. 추가 PC 수집은 기본적으로 웹을 생략했습니다.

분석 전달의 문제

본문을 수집해도 뒤쪽 워크플로우 분석에서는 짧은 표시문으로 줄었습니다. 적은 근거로도 여러 단계를 만들게 하는 요구가 있었습니다.

04 · 활용

근거의 질 확인

본문·날짜·대화 연결·수집 한계를 분석까지 전달합니다.
Teams
열린 앱 단서＋Graph (설정·허용 시)＋날짜 검색 → 원문 → 주변 메시지＋기존 채팅목록 탐색
메일
클래식 Outlook COM＋Windows Search 단서＋Outlook 웹 기간 검색＋선택한 EML/MBOX
새 버튼은 Copilot 수집에 의존하지 않습니다. 기존 일반 실행의 Copilot 보충 옵션은 남아 있습니다. Copilot 요약을 받더라도 직접 확인한 원문과 구분하며, 기억이나 추론으로 누락된 실제 메시지를 복원했다고 간주하지 않습니다.

4. Teams: 방 목록만 보던 방식에서 날짜 검색을 추가했습니다

탐색

Sent: 날짜 검색

하루 단위로 검색합니다. 날짜만 검색하는 동작과 현재 DOM은 회사 화면에서 확인이 필요합니다. 미지원이면 기존 방 탐색을 계속합니다.

확인

검색 결과 → 실제 메시지

방 ID·메시지 ID·날짜를 확인한 원문만 채택합니다. 검색 미리보기를 전체 본문으로 취급하지 않습니다.

문맥

주변 원문도 함께

검증된 앵커 주변의 제한된 메시지를 원본별로 보관합니다. 답글 전체와 모든 과거 대화를 얻었다는 뜻은 아닙니다.

작업 단위 진행과 이미 저장한 원문을 보존합니다. 재시도 과정에서 겹친 메시지는 중복 병합합니다. 검색을 시도한 날 수와 자료가 관측된 날 수는 다른 값입니다.

5. 메일: 앱·웹이 안 되면 선택한 원본 파일을 받습니다

웹으로 가져올 때

받은편지함·보낸편지함의 기간 검색
공식 날짜 범위 구문 사용
목록을 순회하고 확인된 자료 저장
사용자가 본문 포함을 선택하면 원문 확인

보관함·사용자 폴더·온라인 보관함 등 사서함 전체 탐색은 보장하지 않습니다. 검색 결과 상한과 화면 구조의 영향을 받습니다.

파일로 가져올 때

사용자가 Outlook에서 .eml 저장
LM에 파일 또는 폴더 경로 입력
날짜·제목·본문·회신 헤더 읽기
기존 메일 CSV에 중복 제거 후 병합

MBOX도 지원합니다. 자동으로 전체 메일을 내보내지는 않습니다. PST·MSG 직접 파싱과 첨부 본문 읽기는 지원하지 않습니다.

새 Outlook은 클래식 Outlook의 COM 자동화 기능을 제공하지 않습니다. 따라서 “Outlook 설치됨”만으로 COM 수집 성공을 기대할 수 없습니다. Windows Search도 PC에 색인된 자료가 있어야 합니다.

6. 한 줄 단서로 모르는 내용을 만들지 않습니다

아래는 설명용 가상 사례입니다.

제목만 확보

“A설계 검토 건”

누가 수정했는지, 어떤 결론이 났는지, 완료됐는지는 알 수 없음

처리: 업무 분류 단서로 보존. 제목뿐인 단위의 워크플로우 확정·우선순위 집계는 보류.

원문과 응답을 확보

요청: 치수 공차 재검토
응답: 수정안 문서 전달
결정: 시제품으로 검증 후 판단

처리: 각 원문 ID에 연결해 흐름을 해석. 최종 승인·양산 완료까지 추정하지 않음.

‘근거가 연결됨’ ≠ ‘AI 서술의 사실 검증 완료’. AI 응답에 존재하는 원신호 ID가 있어도 그 해석이 맞다는 보증은 아닙니다. 역할·업무 순서·자동화 적합도는 검토 가능한 해석으로 표시합니다.

7. 화면에서 무엇을 확인하나요?

건수

선택 기간 내 고유 메일·Teams 기록. 추가 PC 자료도 함께 확인합니다.

본문

사용 가능한 문맥이 포함된 기록 수. 보호 필터로 제외되거나 발췌된 본문은 한계를 남깁니다.

공백

기간 탐색 미완료·날짜 불명·로그인·미지원 경로와 다음 조치.

사용 순서: 상단 기간 선택 → 메일·Teams만 수집 (웹 포함) → 본문·공백 확인 → 필요 시 EML/MBOX 가져오기 → 수집 자료 분석.

Outlook 웹 본문 포함은 기본 꺼짐입니다. 켜면 메일을 열어 읽음 표시가 달라질 수 있습니다. 가져온 메일의 발신·수신 방향을 확인하지 못하면 내용 단서로만 사용하며, 그 시각으로 근무시간을 추가하지 않습니다.

수집 중단관측 자료 즉시 누적, 기간별 진행 보관UI 변경·예산·결과 상한으로 계속 미완료일 수 있음
0건자료 미확보와 원인을 표시실제로 업무가 없었다는 결론 금지
대화 전체성원문 ID·출처·제한된 문맥 보존전사 전체·과거 전체·삭제 메시지·첨부 전체 보장 불가
회사 Teams 전체 내보내기승인된 Graph/관리자 제공 경로 별도 검토개인용 Teams 내보내기를 회사 계정 기능으로 안내하지 않음
검증 범위: 코드·합성 입력·가짜 브라우저 응답으로 중복 제거, 문맥 전달, 기간 재개, 부족 근거 보류를 검증합니다. 다른 PC의 실제 회사 로그인·DOM·검색 결과·차단 정책에서 수집량이 늘었는지는 해당 PC에서 확인해야 합니다.
