Teams가 버리던 정상 대화를 복원합니다

설치된 Teams·Outlook 앱을 읽지 못할 때에도, 로그인한 웹 화면에서 메시지를 열고 펼치며 읽습니다. 웹에서 읽어낸 평문은 저장하고, 분석에는 앞·중간·끝 발췌를 연결합니다.

이 문서는 구현과 합성 검증 결과를 설명합니다. 실제 회사 PC의 수집 성공이나 모든 버전·전체 기간의 누락 0건을 확인한 보고서는 아닙니다.

로그인할 시간

Outlook 최초 로그인 8초 제한을 고쳤습니다. 두 웹 경로 모두 로그인 화면에서 최대 120초 기다리되 전체 실행 한도를 넘지 않습니다.

실제 PC 원인 미확정

본 PC의 빈 Edge 연결 시험은 성공했습니다. 다른 PC의 회사 계정 수집 성공은 확인하지 못했습니다. 원인표로 실제 중단 단계를 대조해야 합니다.

재설치 전에 현재 실패 기록부터 확인할 수 있습니다. 기존 v25.12의 ‘메일·Teams 근거 확보 → 마지막 실행 원인표 다운로드’에서 summary와 routes를 확인합니다. v25.14는 여기에 브라우저 단계·화면 인식 건수·날짜 집계를 더 남깁니다. 본문·수신인·계정·URL은 이 원인표에 넣지 않습니다.

새 ZIP을 다른 폴더에 풀면 기존 로그인 상태가 자동으로 이어지지 않습니다. 기존 설치 업데이트 시 config·data·report·로그인 프로필을 보존하세요. 아래 그림은 앞선 본문 수집 방식의 설명이며 전체 수집 성공을 인증하는 그림이 아닙니다.

③ Outlook: 대화 한 덩어리 대신 메일 한 건씩

웹 메일 본문 포함을 체크하면 메일을 여는 과정에서 읽음 표시가 바뀔 수 있습니다. 체크를 끄거나 제목 저장을 금지한 설정이면 웹 본문은 수집하지 않습니다.

⑥ 화면에서 확인할 세 숫자

기간 내 고유 기록

날짜를 확인하고 중복을 제거한 관측 자료입니다. 실제 서버 전체 건수는 아닙니다.

본문 포함 · 웹 부분

본문을 읽은 자료와 미펼침·부분 자료를 구분합니다. ‘부분 0건’도 모든 대화의 확보 완료를 뜻하지 않습니다.

날짜 미확정 보류

원문은 관측했지만 요청 기간에 속하는지 확인하지 못한 자료입니다. 기간 건수와 AI 분석에서 제외합니다.
  1. 새 배포본의 표시 버전이 v25.14인지 확인합니다.
  2. 시작일·종료일을 정하고 추가 PC 수집 또는 메일·Teams만 수집을 누릅니다. 웹 메일 본문은 두 버튼에서 기본 포함입니다.
  3. 로그인 창이 나오면 읽을 회사 계정을 확인합니다. 한 번에 전 기간을 확인하기 어렵다면 같은 기간으로 다시 실행합니다.
  4. 메일·Teams 근거 확보 화면의 본문 건수, 부분 수집 이유, 날짜 보류를 확인한 뒤 모은 자료 분석을 실행합니다.

기존 폴더 업데이트는 config·data·로그인 프로필을 보존해야 합니다. 새 ZIP 폴더는 기존 설정과 로그인 상태를 자동으로 가져오지 않습니다. 화면의 웹 수집 사용 선택이 이번 실행에만 적용되며 기존 웹 사용 설정보다 우선합니다. 설정 파일은 바꾸지 않습니다. 수집 버튼은 Copilot·AI를 자동 호출하지 않습니다.

계속 남는 범위

권한 밖 자료, 보존 기간이 지난 자료, 웹에서 노출되지 않는 원문, 첨부파일 내용, 삭제·수정 이력 전체, 모든 채널·답글의 완주, 모든 웹 화면 버전 호환은 보장하지 않습니다. 웹 수정 시각을 검증하지 못한 경우 더 풍부한 기존 본문을 보존하므로, 나중에 짧게 수정된 서버 원문과 다를 수 있습니다. 본문 일부로 업무 과정·역할·성과를 확정하거나 미수집 내용을 AI의 기억으로 채우지 않습니다.
