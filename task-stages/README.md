## VV-3 연결 구조

사내 시스템(PLM 과제관리 · GIPS 발주 · EGIS 특허 · 시험 결과) ⇄ VV-3 허브(RFQ 지식 DB · 이력 저장소 · 공통 이름표·판정 기록) ⇄ AL-1 설계 · VV-1 가상검증 · 피드백(RSI·보정)

- 커넥터는 시스템마다 읽기 전용 MCP 서버 하나. 개발(Claude Code)은 합성 데이터 쪽, 운영(사내 LangGraph)은 실데이터 쪽에 같은 커넥터를 붙인다
- RFQ 지식 DB: 업체별·제품별 RFQ와 대응 제품 성능 — 숫자는 표, 문장은 벡터, 출처를 다는 RAG. 고객 RFQ는 사내 서버만
- 이력 저장소: 요구 → 설계안 → 가상 결과 → 실물 결과를 공통 ID로 한 줄 — AL-1 RSI·VV-1 보정의 재료
- 안쪽 고리(AL-1 설계 ⇄ VV-1 가상검증)는 설계안마다, 바깥 고리(실물 → 피드백 → 다음 RFQ)는 시제품 차수마다 돈다

## 로직 검토 — 단계 순서는 셋 다 맞고, 고칠 것은 9가지

1. **VV-3를 ‘연결·관리’로 바꾼다.** 설계는 AL-1, 가상검증은 VV-1. VV-3는 커넥터(PLM·GIPS·EGIS), RFQ 지식 DB, 실물 검증 연결, 피드백 이력의 주인(위 표).
1. **VV-3 1단계를 지금 시작한다.** AL-1·VV-1 4단계의 ‘목표 성능’과 ‘RFQ 판정 기준’은 VV-3 RFQ 지식 DB가 공급한다.
1. **VV-1 2단계 광학은 AL-1 광학 플러그인(’28.10)보다 1년 이르다.** ’27에는 광학 설계 도구 결과를 직접 읽는 브리지로 시작한다.
1. **조립 전 판정은 하나로.** VV-1 3단계와 VV-3의 VP 판정을 하나의 절차(’28.6)로 묶고 VV-3가 회의·기록을 맡는다. VV-1은 시스템 성능, AL-1은 HW 해석 근거를 낸다.
1. **실측 대조를 앞당긴다.** VV-1 엔진의 첫 실측 대조를 ’28.6에서 ’27.3(벤치 5~8셀)으로 옮기고, VV-3 실물 결과 기록도 이때 시작한다.
1. **사내 시스템 커넥터는 VV-3가 한 번 만든다.** 보안 부담이 작은 조회부터 — PLM 과제·GIPS 발주 ’27.9 → EGIS 특허 ’27.12 → PLM 도면·BOM ’28.1(보안 승인 ’27.12 뒤). AL-1·VV-1이 같이 쓴다.
1. **RFQ 지식 DB는 숫자를 표로 뽑는다.** 요구값과 대응 성능은 표로 비교하고 문장은 벡터로 찾는다. 고객 RFQ는 사내 서버만, 업체별 열람 권한을 검색에도 적용한다.
1. **피드백(RSI)은 실물 쌍이 쌓여야 돈다.** AL-1 ‘스스로 개선’은 결과·채택·실물 기록으로 탐색 전략·템플릿·대리모델을 갱신하는 데까지, 최적화기가 주도하고 사람이 채택한다. 첫 반영은 쌍이 도메인당 20을 넘은 뒤(’28.12).
1. **사람이 먼저 걸린다.** 4묶음 4.0명 기준으로 계획된 일이 약 2배다. 새 연결 일(약 14 인월)은 대부분 가장 바쁜 AI·ML·MLOps로 가므로, RFQ 지식 DB는 AL-1 케이스 DB 틀을 재사용하고, 커넥터는 읽기 전용으로 작게, 살 수 있는 제품은 산다(외주 없음). ’28 범위와 인원은 ’27.6.30에 정한다.

과제 사이에 주고받는 것, 과제별 점검표(8개 항목), ’27 계획의 VV-3 일이 옮겨 가는 곳, 단계별 주로 맡는 묶음은 HTML에 있습니다.
